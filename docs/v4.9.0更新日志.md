## 问题2 详解：resize 防抖

### 根因
prompt_toolkit 的 `_on_resize` 每次 SIGWINCH 都执行 erase+CPR请求+重绘：
- 拖动窗口边缘连续触发几十次 SIGWINCH
- erase 依赖上次渲染的光标位置，终端 reflow 后位置已漂移
- 多个 CPR 请求/响应异步交错，尺寸与光标行号错配
- 中间态重绘与 erase 互相踩踏 → 每次 resize 残留一行 ❯

### 修复（resize_fix.py）
`install_resize_fix()` 将 `Application._on_resize` 替换为防抖版本：
- 连续 SIGWINCH 取消前一次未执行的定时器，仅执行最后一次（100ms）
- 拖动过程中不做 erase/redraw（旧布局暂时保留，终端自行 reflow）
- 拖动结束后一次干净的 erase+redraw，消除中间态错乱

## 问题3 详解：统一交互输入

Python 内置 `input()` 使用 readline/终端规范模式，与 prompt_toolkit 主输入框
是两套渲染体系，中文/emoji 退格行为不一致。新建 `prompt_utils.py`：

```python
ask_text("模型名称: ")           # 取消返回默认值
ask_text_or_none("确认执行? ")   # 取消返回 None（确认场景区分空输入）
```

全局 49 处内置 input() 全部替换（9个命令文件 + tool_executor 确认 + ask_user），
所有交互输入统一走 prompt_toolkit + 字素簇宽度补丁。

## 问题4 详解：edit 预览 rich.Table

- **宽屏（≥110列）**：左右并排表格（原内容 | 新内容），表头红/绿底色
- **窄屏（<110列）**：上下堆叠两个表格
- 长行自动折行（rich 原生，不截断丢失内容），行号黄色标识
- `_term_width()` 改用 `os.get_terminal_size(fileno)` ioctl 实时查询：
  `shutil.get_terminal_size()` 优先读取可能过期的 COLUMNS 环境变量，
  是窗口调小后仍按旧宽度渲染导致交叉显示的根因之一

## 问题5 详解：并行子Agent状态板

- `rich.Live`（transient 模式）每 250ms 刷新状态板：
  子Agent名 | 任务 | 当前步骤（🚀启动/💭AI思考中/🔧工具名） | 状态（⏳/🔄/✅/❌）
- 当前步骤通过包装 `tool_executor._on_tool_execute` 实现：
  回调在执行线程中触发，按线程ID定位子Agent
- 全部完成后状态板自动清除（transient），只留一行静态总结+各Agent结果摘要
- 不再回显子Agent完整执行细则（避免多路输出混杂难辨）
- 最大并发 4 → 10；单次最多子任务 6 → 10

## 附录A：v4.9.0 补丁修复记录（后续反馈）

### Bug 1: delegate_task 报错 'SubAgentScheduler' object has no attribute 'delegate_and_run'
- **根因**：v4.9.0 插入 `_SubAgentLiveBoard` 类时位置不当（在 run_parallel 之后、delegate_and_run 之前），导致 delegate_and_run/get_result/cleanup/cleanup_all/get_active_count/get_status_summary 共6个方法被吞进 _SubAgentLiveBoard 类
- **修复**：把这6个方法移回 SubAgentScheduler，_SubAgentLiveBoard 只保留 start/stop/__rich_console__
- **教训**：插入新类时必须确认后续方法的类归属；并行测试没覆盖串行 delegate_and_run 路径导致漏测

### Bug 2: edit "找到N处匹配" 报错不友好
- **改进1**：多处匹配错误信息附带每处匹配的行号+内容预览，AI可直接据此构造唯一old_str重试
- **改进2**：edit 工具新增 `replace_all` 参数（boolean，默认false），确需全部替换时 AI 可设 replace_all=true，成功后报告替换处数
