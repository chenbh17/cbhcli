# v5.1.1 更新日志 - Agent 链条 Web 端权限继承 + 执行过程可见 + Fallback 修复

## 概述

v5.1.1 修复 Agent 链条功能的五个问题：① 下游 Agent 模型调用失败后不自动 fallback；② Web 端下游 Agent 权限未继承元 Agent 权限模式（不弹确认框）；③ Web 端看不到下游 Agent 执行过程（输出去了服务器终端）；④ Web 端下游 Agent 的 ask_user 不可见（去了 CLI 终端）；⑤ Web 端下游 Agent 内容显示逐词换行（每段文本单独 renderMd 产生碎片 HTML）。修改 6 个文件，无新增文件。

---

## 修复 1：下游 Agent 模型 Fallback

**问题**：下游 Agent 的模型调用失败时不自动切换备用模型，直接报错终止。

**根因**：`ChainExecutor.execute()` 创建下游 `AIHandler` 时未注入 `fallback_models`，默认空列表导致 `_get_ai_response` 中 `if not self.fallback_models: raise` 直接抛出异常。

**修复**：`agent_chain.py` 中创建 `AIHandler` 后注入全局备用模型列表：

```python
from cbhcli_pkg.config.global_config import GlobalConfig
handler.fallback_models = GlobalConfig().get_fallback_models()
```

---

## 修复 2：Web 端链条权限继承

**问题**：Web 端下游 Agent 的工具执行全部自动放行，不弹确认框。标准模式下元 Agent 的危险操作弹确认框，但下游 Agent 的所有操作直接执行。

**根因（两层）**：
1. `ChainExecutor` 对 Web 端硬编码 `no_more_confirmations = True`，跳过所有确认
2. 即使改为传入 `_confirm_callback`，`_confirm_execution` 先检查 `no_more_confirmations`（Web session 的 tool_executor 为 `True`），回调永远执行不到

**修复方案**（3 个文件协同改动）：

### `tool_executor.py` — 确认回调 + 优先级修正

- 新增 `_confirm_callback` 属性：`(tool_name, arguments) -> bool`
- `_confirm_execution` 检查顺序修正为：
  ```
  只读工具 → _confirm_callback（优先） → no_more_confirmations → CLI 交互
  ```
  回调优先于 `no_more_confirmations`，因为回调内部自行处理 `all` 逻辑。

### `agent_chain.py` — 权限继承逻辑

- 删除 Web 端硬编码 `no_more_confirmations = True`
- Web 端（`_confirm_callback` 存在时）：设置回调 + 强制 `no_more_confirmations = False`
- CLI 端（无回调时）：继承上游 executor 的 `no_more_confirmations`

```python
_confirm_cb = getattr(self._app, '_chain_confirm_callback', None)
if _confirm_cb is not None:
    downstream_executor._confirm_callback = _confirm_cb
    downstream_executor.no_more_confirmations = False  # 回调优先
else:
    _upstream_executor = getattr(self._app, 'tool_executor', None)
    if _upstream_executor is not None:
        downstream_executor.no_more_confirmations = getattr(
            _upstream_executor, 'no_more_confirmations', False)
```

### `server.py` — Web 端 SSE 确认流程

`_react_loop` 中 `call_agent` 工具执行改为**后台线程 + 事件队列轮询**模式：

```
call_agent 工具执行流程（Web 端）：
  │
  ├─ 1. 创建通信原语（queue + threading.Event×2 + response holder×2 + no_more flag）
  ├─ 2. 设置 3 个回调到 app_proxy：
  │     ├─ _chain_confirm_callback（工具确认）
  │     ├─ _chain_ask_user_callback（ask_user 提问）
  │     └─ _chain_event_callback（执行过程事件）
  ├─ 3. run_in_executor 启动下游 Agent 后台线程
  ├─ 4. 轮询事件队列，分发处理：
  │     ├─ _chain_confirm → 权限引擎检查 → SSE tool_confirm 弹窗 → 等待响应 → 回传
  │     ├─ _chain_ask_user → SSE ask_user 弹窗 → 等待回答 → 回传
  │     ├─ _chain_evt_content → SSE chain_call_content
  │     ├─ _chain_evt_reasoning → SSE chain_call_reasoning
  │     ├─ _chain_evt_tool_call → SSE chain_call_tool
  │     └─ _chain_evt_tool_result → SSE chain_call_tool_result
  ├─ 5. 下游线程完成 → 获取结果 → 清除 3 个回调
  └─ 6. 返回 ToolResult
```

**效果**：Web 端下游 Agent 与 CLI 完全一致——standard 弹确认框（带 `[agent_name]` 标识）、auto 自动放行、readonly 禁止修改、yolo 全放行（红线警告）。

## 修复 3：Web 端下游 Agent 执行过程可见

**问题**：Web 端调用 `call_agent` 后，下游 Agent 的思考内容、工具调用、回复文本全部输出到服务器终端（stdout），Web UI 上看不到任何执行过程。

**根因**：`AIHandler` 的 `_chain_content_callback`/`_chain_tool_callback` 属性被 `ChainExecutor` 设置但代码中从未调用；下游 Agent 的 `print()` 输出在 Web 端丢失。

**修复方案**（3 个文件协同改动）：

### `ai_handler.py` — 链条事件回调

- 新增 `_chain_event_callback` 属性 + `_emit_chain_event()` 方法
- 在 4 个位置调用回调：
  - `_stream_with_model` reasoning → `_emit_chain_event("reasoning", content=...)`
  - `_stream_with_model` content → `_emit_chain_event("content", content=...)`
  - `_execute_tools` 工具调用前 → `_emit_chain_event("tool_call", tool_name=..., arguments=...)`
  - `_execute_tools` 工具执行后 → `_emit_chain_event("tool_result", tool_name=..., success=..., ...)`

### `agent_chain.py` — 回调传递

- 从 app 上下文读取 `_chain_event_callback` 注入到下游 AIHandler

### `server.py` — SSE 事件推送

- `_chain_event_cb` 回调将事件推入队列
- `_react_loop` 轮询队列并 yield SSE 事件

**前端新增 SSE 事件**：

| 事件 | 数据 | 说明 |
|------|------|------|
| `chain_call_start` | `{agent_name, task}` | 下游 Agent 调用开始，创建折叠区块 |
| `chain_call_content` | `{agent_name, content}` | 下游 Agent 回复内容（流式） |
| `chain_call_reasoning` | `{agent_name, content}` | 下游 Agent 思考内容（流式） |
| `chain_call_tool` | `{agent_name, tool_name, arguments}` | 下游 Agent 工具调用 |
| `chain_call_tool_result` | `{agent_name, tool_name, success, output}` | 下游 Agent 工具结果 |
| `chain_call_ask_answered` | `{agent_name, answer}` | 下游 Agent ask_user 已回答 |
| `chain_call_end` | `{agent_name, success}` | 下游 Agent 调用完成 |

## 修复 4：Web 端下游 Agent ask_user 可见

**问题**：下游 Agent 执行 `ask_user` 工具时，问题去了 CLI 终端，Web 用户看不到也无法回答。

**根因**：`ask_user` 工具的 `execute()` 调用 `ask_text_or_none()` 终端交互，在 Web 端后台线程中无法工作。

**修复方案**（3 个文件协同改动）：

### `tool_executor.py` — ask_user 回调

- 新增 `_ask_user_callback` 属性：`(question, options, allow_multiple) -> str`
- `execute()` 中拦截 `ask_user`：回调设置时走回调，否则走正常工具注册表

```python
if tool_name == "ask_user" and self._ask_user_callback is not None:
    answer = self._ask_user_callback(
        arguments.get("question", ""),
        arguments.get("options", []),
        arguments.get("allow_multiple", False),
    )
    return ToolResult(success=True, output=f"用户回答: {answer}")
```

### `agent_chain.py` — 回调传递

- 从 app 上下文读取 `_chain_ask_user_callback` 注入到下游 executor

### `server.py` — SSE 路由

- `_chain_ask_user_cb` 回调将 ask_user 请求推入队列，阻塞等待回答
- `_react_loop` 轮询到 ask_user 请求后 yield SSE `ask_user` 事件（带 `chain_agent` 标识）
- 用户在 Web UI 回答后，响应经 `cs.wait_response()` 回传下游线程

### `app.js` — 前端标识

- `handleConfirm` 支持 `chain_agent` 字段，确认框标题显示 `[agent_name]` 标识
- `handleAskUser` 复用现有流程（SSE `ask_user` 事件已带 `chain_agent` 字段）

## 修复 5：Web 端下游 Agent 内容逐词换行

**问题**：Web 端下游 Agent 的回复内容显示为逐词/逐字换行的碎片文本，无法正常阅读。

**根因**：`chain_call_content` SSE handler 对每个流式文本块单独调用 `renderMd()` 再拼接 HTML——`renderMd("测试")` 产出 `<p>测试</p>`、`renderMd("**")` 产出 `<p>**</p>` 等，每个词被包成独立块级元素导致换行显示。

**修复**：`app.js` 中 `chain_call_content` handler 改为累积原始文本到 `_raw` 属性，每次收到新文本时整体重新 `renderMd(textEl._raw)`——与主会话 `content` handler 同样的模式：

```javascript
// 修复前（错误：逐段 renderMd 产生碎片 HTML）
p.innerHTML = (p.innerHTML || "") + renderMd(d.content || "");

// 修复后（累积原始文本，整体重新渲染）
textEl._raw = (textEl._raw || "") + (d.content || "");
textEl.innerHTML = renderMd(textEl._raw);
```

**效果**：下游 Agent 的回复内容正常流式渲染，Markdown 格式正确（加粗/列表/代码块等不再被拆散）。

## 设计说明

### 为什么用回调而不是直接传参？

`ChainExecutor` 是 CLI 和 Web 共用的，但确认/ask_user/输出机制不同：
- CLI：终端交互输入（`ask_text_or_none` + `print`）
- Web：SSE 事件 + API 响应（异步）

通过回调注入（`_confirm_callback`/`_ask_user_callback`/`_chain_event_callback`），两端共用同一份 `ChainExecutor` 代码，仅在交互行为上通过回调分离。CLI 端不设置回调（`getattr` 返回 `None`），走默认终端行为；Web 端在执行 `call_agent` 前设置回调，执行后清除。

### 为什么用队列+轮询而不是直接 await？

下游 Agent 在后台线程中同步执行（`run_in_executor`），其工具确认和 ask_user 也是同步阻塞的（`threading.Event.wait()`）。SSE 生成器是异步的，无法直接在同步回调中 `await`。因此用 `queue.Queue` 做线程→异步的事件传递，用 `threading.Event` 做异步→线程的响应传递，SSE 生成器轮询队列实现双向通信。

### 回调优先级设计

`_confirm_execution` 检查顺序：
```
只读工具 → _confirm_callback → no_more_confirmations → CLI 交互
```

回调优先于 `no_more_confirmations` 是因为 Web 端 session 的 `tool_executor` 固定为 `True`（Web 的确认在 `_react_loop` 层面处理而非 ToolExecutor 层面），如果先检查 `no_more_confirmations` 会导致回调永远不被执行。回调内部通过 `_chain_no_more[0]` 标志自行处理 `all` 逻辑。
