# v5.1.4 更新日志

## 修复：模型调用 400 错误（tool_calls 消息序列 + thinking 参数格式 + effort 冲突）

本次更新修复了三个导致模型 API 调用报 400 错误的问题：DeepSeek 等模型在工具调用/Agent 链条期间偶发 `tool_calls must be followed by tool messages` 错误、thinking 参数传布尔值被拒、thinking=off 时配置 reasoning_effort 冲突。

---

## 一、修复 tool_calls 消息序列不完整导致的 400

### 错误现象

```
⚠️ 主模型调用失败: API请求失败: 400 - {"error":{"message":
"An assistant message with 'tool_calls' must be followed by tool messages
responding to each 'tool_call_id'. (insufficient tool messages following
tool_calls message)", ...}}
```

在工具调用期间或使用 Agent 链条（call_agent）时偶发。

### 根因（3 个触发场景）

| # | 场景 | 说明 |
|---|------|------|
| 1 | **图片消息插队**（核心） | 模型一次返回多个 tool_call 且其中某个工具（如 image 工具直发模式）成功返回图片时，带图 user 消息被**插在 tool 消息之间**：`assistant(tool_calls) → tool(1) → user(图片) → tool(2)`。DeepSeek 等 API 严格要求 tool 消息紧跟 assistant(tool_calls) |
| 2 | **Web 端 abort 中断** | `assistant(tool_calls)` 消息已记录到会话，但用户中断（abort）时直接 return，剩余工具未执行 → tool 消息缺失 |
| 3 | **CLI 端 Ctrl+C 中断** | `KeyboardInterrupt` 继承 `BaseException`，不被 `except Exception` 捕获，工具执行循环中断 → 部分 tool 消息缺失 |

### 修复方案（三层防护）

**① 源头修复：图片 user 消息延迟追加**

- `cbhcli_pkg/core/ai_handler.py` `_execute_tools()`：图片 user 消息先收集到 `pending_image_msgs`，**所有 tool 消息添加完成后**再统一追加到会话（CLI）
- `cbhcli_pkg/web/server.py` `_react_loop()`：同样延迟到工具循环结束后统一追加（Web）

**② 中断补全：abort / Ctrl+C 时补 tool 消息**

- `ai_handler.py`：`except KeyboardInterrupt` 中为所有未执行的 tool_call 补占位 tool 消息（"工具执行被用户中断"），再 re-raise
- `server.py`：新增 `_fill_aborted_tool_msgs()`，abort 时（工具循环开头 + ask_user 等待超时两处）为剩余工具补占位 tool 消息

**③ 防御性兜底：发送前自动修复消息序列**

新增模块级函数 `repair_tool_messages(messages)`（`cbhcli_pkg/core/ai_handler.py`）：

- 扫描每个带 `tool_calls` 的 assistant 消息及其后的工具区（tool 消息 + 其间插入的 user 消息）
- **缺失的 tool_call_id 自动补占位 tool 消息**（内容提示模型"结果缺失，请继续任务"）
- **插队的 user 消息自动移到工具组之后**（不影响正常的新轮次 user 消息）
- 不修改会话内部状态，仅修复发送给 API 的消息列表，幂等

调用点（覆盖全部执行路径）：
- CLI：`AIHandler.process_request()` 发送前
- Web：`_react_loop()` 发送前
- 子 Agent（delegate_task）、Agent 链条（call_agent）均走 AIHandler → 自动覆盖
- 历史会话恢复后同样生效（发送前统一修复）

## 二、修复 thinking 参数格式错误（布尔值 → ThinkingOptions 结构体）

### 错误现象

```
⚠️ 主模型调用失败: API请求失败: 400 - {"error":{"message":
"Failed to deserialize the JSON body into the target type:
thinking: invalid type: boolean `false`, expected struct ThinkingOptions", ...}}
```

配置 thinking 参数（无论 on/off）后调用报错。

### 根因

DeepSeek 等 API 期望 `thinking` 参数为 **`{"type": "enabled"}` / `{"type": "disabled"}` 结构体**（ThinkingOptions），而 v5.1.3 将用户配置的布尔值 `true/false` 直接传给 API。

### 修复

`cbhcli_pkg/core/model.py` 新增 `_normalize_thinking()` 静态方法，`_get_extra_payload()` 发送前统一规范化：

| 配置值 | 发送给 API |
|--------|-----------|
| `True`（bool） | `{"type": "enabled"}` |
| `False`（bool） | `{"type": "disabled"}` |
| `"on"` / `"true"` / `"1"` / `"yes"` | `{"type": "enabled"}` |
| `"off"` / `"false"` / `"0"` / `"no"` | `{"type": "disabled"}` |
| dict（如 `{"type": "enabled", "budget_tokens": 8000}`） | 原样传递 |

**存量配置自动生效**：已保存布尔值的模型无需重新配置，读取后自动规范化。

## 三、thinking=off 时禁止配置 reasoning_effort（冲突提醒 + 校验）

### 错误现象

thinking 配置为 off 且同时配置 reasoning_effort 时，API 报 400：

```
thinking options type cannot be disabled when reasoning_effort...
```

### 联网调研结论

- ✅ **确认**：DeepSeek V4 API 中 `thinking: {"type": "disabled"}` 时**不允许**携带 `reasoning_effort`，会报 400
- 补充：DeepSeek API **不传 thinking 参数时默认开启思考模式**（hermes-agent issue #15700 确认）；思考模式支持 `reasoning_effort`（high/max 等档位）

### 修复（4 层防护）

**① CLI 交互提醒（/model add、/model config）**

- `cbhcli_pkg/commands/model_cmd.py` `_add_model()`：输入 reasoning_effort 时若 thinking=off → 打印提醒"⚠️ thinking 已关闭(off)，此时不能配置 reasoning_effort（API 会返回 400 错误）"，**让用户重新输入**（留空 / none 结束；如需 effort 需将 thinking 改为 on）
- `_config_model()`：
  - thinking 改为 off 且已有 reasoning_effort → **自动清除**并提醒
  - reasoning_effort 输入环节同样循环校验提醒

**② Web 前端禁用 + 校验（app.js）**

- thinking 下拉选择"关闭 (false)"时，reasoning_effort 输入框**自动禁用**，提示文案变为红字"⚠️ thinking 已关闭(off)，不能配置 reasoning_effort（API 会报 400）"
- 保存时二次校验：thinking=false 且 effort 非空 → toast 警告并中止提交

**③ Web 后端 API 校验（server.py）**

- `POST /api/models`（添加）与 `PUT /api/models/{name}`（更新）：`thinking is False and reasoning_effort` → 返回 400 明确提示

**④ 请求层兜底（model.py）**

- `_get_extra_payload()`：`thinking is False` 时**自动忽略 reasoning_effort**（不传给 API），防止存量脏配置触发 400

## 影响范围

- **CLI 端**：ReAct 工具调用循环（图片直发、Ctrl+C 中断）、/model add、/model config
- **Web 端**：模型管理视图（thinking/effort 联动禁用）、/api/models 增改接口、ReAct 循环（abort 中断、图片直发）
- **请求层**：thinking 参数格式规范化（DeepSeek 兼容）、thinking=off 时 effort 忽略
- **Agent 链条 / 子 Agent**：走 AIHandler 统一修复，无需单独改动
- **兼容性**：存量模型配置（布尔 thinking）自动规范化；未配置 thinking/effort 的模型行为与旧版完全一致
