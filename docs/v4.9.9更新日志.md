## 1. 权限规则引擎（Governance 治理层）

**新文件 `core/permissions.py`（~480行）**

四档权限模板，`Shift+Tab` 循环热切换（Claude Code 同键位），`/mode` 命令直接设置：

| 模式 | 语义 |
|------|------|
| 🔒 `readonly` | 只读模式：write/edit/python 直接拒绝，terminal 仅白名单只读命令（ls/cat/git status...） |
| 🟢 `standard` | 标准模式（默认）：deny 红线硬阻断 + ask 人审 + allow 免打扰 |
| 🟡 `auto` | 自动模式：cwd 内写操作、python、pytest/git commit 等开发命令自动放行；deny 红线仍生效 |
| 🔴 `yolo` | 最高权限：全部零确认直接执行；deny 降级为红色警告留痕（`yolo_keep_deny: true` 可强制仍阻断） |

**规则语法**（借鉴 Claude Code permissions）：
- `terminal(git status:*)` — 命令前缀匹配
- `edit(/project/**)` `write(**/.env*)` — 路径 fnmatch
- `python(*)` — 工具级
- 判定优先级：**deny > ask > allow > 默认**；deny 连 `all` 也不能豁免（只有 yolo 能降级）

**内置规则集**：
- deny 红线 14 条：`rm -rf /`、`dd of=/dev/*`、`mkfs`、`shutdown`、fork 炸弹、写 `.env`/`.git`/`id_rsa`/`*.pem`
- ask 15 条：`git push`、`git reset --hard`、`rm:*`、`sudo:*`、`pip uninstall`、`curl/wget`、`ssh/scp`、`kill`
- allow 只读命令若干；auto 模式追加 git add/commit、pytest、python、make、npm 等

**交互优化**：确认框从 `[Y/n/all]` 扩展为 `[Y/n/all/always]`——选 `always` 自动提炼一条 allow 规则（如 `terminal(pytest:*)`、`edit(/project/**)`）写入 `~/.cbhcli/permissions.json`。

**YOLO 防误触**：CLI 按 Shift+Tab 进入 yolo 需 3 秒内再按一次确认；`/mode yolo` 与 Web 端切换均需二次确认。

**模式感知**：状态栏新增彩色模式指示块（蓝/绿/黄/红）；切换时系统提示原地注入模式说明（readonly 时明确告知模型"只能看不能改"，避免白尝试）；`/new` 后回落默认模式。

## 2. 死循环检测与熔断（Reliability 可靠性层）

**新文件 `core/loop_detector.py`（~180行）**

**工具调用循环（ToolCallTracker）**：
- 精确重复：同工具+同参数（规范化 JSON 哈希签名）连续 3 次 → **软警告**附加到工具结果尾部返回模型（"请换策略"）；第 4 次起 → **硬阻断**跳过执行，伪造 ToolResult 告知模型必须换方式；单请求内干预 3 次仍无效 → **熔断终止本轮任务**并告知用户建议
- 周期震荡：检测 A→B→A→B 周期 p∈[2,5] 模式完整重复 2 轮 → 软警告
- 前两级模型无感继续跑任务，只有彻底没救才打扰用户；熔断失败不进入反思重试（避免雪上加霜）

**文本复读循环（TextLoopDetector）**：
- 流式 reasoning/content 中尾部 150 字符块出现 ≥3 次 → 判定复读 → 截断流式输出，提示注入 assistant 内容让模型下轮看到"已被截断，请简明继续"

Web 端 ReAct 循环全量同步，新增 SSE 事件 `loop_detected`。

## 3. Hooks 钩子系统（Lifecycle 生命周期层）

**新文件 `core/hooks.py`（~240行）**

生命周期 6 事件自动执行用户自定义 shell 命令（硬规则，不依赖模型自觉）：

| 事件 | 时机 | 语义 |
|------|------|------|
| `SessionStart` | 会话开始/重置后 | stdout 打印给用户 |
| `UserPromptSubmit` | 用户输入发模型前 | stdout 追加为用户上下文（如注入 git 分支） |
| `PreToolUse` | 工具执行前 | 退出码 0=放行 / **2=拦截（stderr 反馈模型）** / 其他=警告 |
| `PostToolUse` | 工具执行后 | stdout 追加为模型反馈（自动跑测试/格式化） |
| `SubagentStop` | 子Agent结束 | stdout 打印 |
| `Stop` | AI 回复完成 | 通知/自动 git commit |

- 配置：`~/.cbhcli/hooks.json`（全局）+ `<agent工作空间>/hooks.json`（Agent级合并）
- 协议与 Claude Code 一致：JSON 经 stdin 传入（event/tool_name/arguments/result/agent/cwd/session_id），超时 10s 强杀，钩子异常只警告绝不阻塞主流程
- 安全红线：仅从信任位置加载且校验文件属主，**不支持从项目目录加载**（防恶意仓库投毒）
- matcher 支持 `terminal`、`write|edit`、`mcp_fs_*` 通配

## 4. 文件检查点回滚（Execution 执行环境层）

**新文件 `core/checkpoint.py`（~190行）**

- write/edit 执行前自动备份目标文件到 `<工作空间>/backups/`（manifest.jsonl 清单）
- 文件原本不存在时记录 `existed=false`，undo 时删除新建文件
- 保留最近 50 份，超出自动清理
- `/undo` 回滚最近一次，`/undo list` 查看备份，`/undo <ID>` 回滚指定

## 5. 调用链追踪（Observability 可观测性层）

**新文件 `core/tracer.py`（~110行）**

每次工具调用（名称/参数摘要/权限判定/耗时/成败/错误）、权限拦截、模式切换、循环熔断、上下文压缩等事件自动追加到 `<工作空间>/history/traces/<session_id>.jsonl`。只追加、不读取、永不抛异常——可观测性不影响主流程。
