# CBHCLI v5.2.6 更新日志

**核心变更：每轮对话自动保存会话（CLI / Web / Jupyter / exec 四端全覆盖）+ 切 Agent 保存目录修复**

---

## 一、背景问题

v5.2.5 及之前，会话只在"结束/切换"时保存（CLI 的 `/new` `/reset` `/resume` `quit`；Web/Jupyter 的 reset / load / switch_model 让位；exec 的运行结束 finally）。**应用异常退出（崩溃、kill -9、关终端、Web/Jupyter 服务重启、SSE 连接断开）时，当前活动会话完全丢失**，聊了半天的对话无法恢复。

## 二、修复方案：每轮对话结束自动落盘

### 1. `SessionHistoryManager.save_session` 幂等化（core/session_history.py）

- **同 session_id 再次保存时覆盖更新同一文件**（glob `*_<session_id>.json` 定位，文件名 `时间戳_会话ID.json` 不变），而不是每次新建文件
- 覆盖时**保留首次保存的 `created_at`**（会话创建时间语义），更新 `messages` / `message_count`
- 效果：一个会话对应一个文件。每轮自动保存 + `/new` 定稿保存 + quit 保存等多次调用幂等，不产生重复文件；exec `-c` 多轮串联也不再累积同 id 多文件（顺带改善）
- session_id 为 uuid4 / HHMMSS，不含 glob 特殊字符；含 `*?[]` 的 id 直接走新建分支防御

### 2. CLI 每轮自动保存（core/app.py）

- 新增 `CBHCLIApp._autosave_session()`：`autosave_history` 开关 + `messages > 1` 条件 + try/except 静默
- `_handle_ai_request` 将 `process_request` + Stop 钩子包进 **try/finally**，每轮对话结束（正常回复 / Ctrl+C 中断 / 请求异常）统一落盘
- 覆盖场景：Ctrl+C 中断轮（`process_request` 内部已捕获 KeyboardInterrupt，中断时的部分消息也在 session 中一并保存）、网络异常轮

### 3. Web / Jupyter 每轮自动保存（web/server.py）

- `_react_loop` 重构为 **wrapper + `_react_loop_inner`**（原函数体改名零改动）：wrapper `async for` 转发事件，**try/finally 兜底**，finally 调用新增的 `_autosave_web_session(cs)`
- 覆盖 `_react_loop` 全部出口：`done` / `aborted`（流式中断、工具确认中断、ask_user 超时中断）/ `error` / 死循环熔断 / 达到最大轮数 / **SSE 连接断开**（客户端断开时框架 aclose 生成器触发 finally）
- Jupyter 插件（cbhcli-jupyter）`from cbhcli_pkg.web.server import _react_loop` 直接复用 wrapper，**零改动自动生效**
- 保存为纯同步文件 IO（消息量级下 <10ms），finally 中不 await，GeneratorExit 场景安全

### 4. exec 保持 `--no-save` 语义（core/exec_runner.py）

- v5.2.6 起 `_handle_ai_request` 的 finally 每轮自动落盘，`--no-save` 需一并关闭：`_build_app` 中 `args.no_save` 时设置 `app.autosave_history = False`，保证完全不留痕
- exec 自身的运行结束 finally 保存保留（幂等覆盖，双保险无害）

### 5. 顺带修复：切 Agent 存错目录（core/app.py `_load_agent`）

- **旧 bug**：`_load_agent` 先把 `session_history` 重建为**新 Agent** 的工作空间（第 512 行），再由 `_reset_session(save_current=True)` 保存旧会话（第 541 行）→ **旧 Agent 的当前会话被误存到新 Agent 的 history 目录**，回头在旧 Agent 的 `/history` 里找不到
- **修复**：保存逻辑移到 `_load_agent` 函数开头（旧组件尚未被替换、`session_history` 尚指向旧 Agent 时执行 `_autosave_session()`），尾部改 `_reset_session(save_current=False)` 跳过重复保存

## 三、行为变化说明

| 场景 | 旧行为 | 新行为 |
|------|--------|--------|
| CLI 崩溃 / kill / 关终端 | 当前会话全丢 | 最多丢正在生成的当前轮 |
| Web/Jupyter 服务重启 | 所有内存活动会话全丢 | 已完成轮均已落盘，可从历史会话恢复 |
| Web SSE 连接断开 | 会话只在内存 | 断开时触发 finally 落盘 |
| 多次保存（自动 + /new + quit） | 每次新建文件，文件累积 | 幂等覆盖，一 会话一文件 |
| exec -c 多轮串联 | 同 id 累积多个文件 | 覆盖更新同一文件 |
| exec --no-save | 不保存 | 依旧完全不保存（自动保存同步关闭） |
| /agent use 切换 | 旧会话误存到新 Agent 目录 | 正确存到旧 Agent 目录 |

## 六、遗留说明

- Web/Jupyter 服务重启后，活动会话仍在内存中丢失，但已落盘的对话可通过"历史会话"（`/resume` / chat/load）恢复；未做"服务重启自动恢复内存会话"
- 每轮自动保存在默认路径下开启，暂未提供配置项开关（exec `--no-save` 除外）
