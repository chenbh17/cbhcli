# v5.0.0 更新日志 — Web AI 发送文件/图片 + 死循环检测修复 + 子Agent上限提升

## 概述

v5.0.0 聚焦 Web 界面体验增强和死循环检测误报修复。核心变更三项：Web 端 AI 可主动向用户发送文件和图片、死循环周期震荡检测从工具名序列改为签名序列（修复误报）、子 Agent 并行上限统一为 100。

---

## 1. Web AI 发送文件/图片（新功能）

**修改文件**：`web/server.py`、`web/static/js/app.js`、`web/static/css/style.css`、`tools/registry.py`

### 功能说明

Web 界面中 AI 现在可以主动向用户发送文件和图片，三层发送机制：

| 方式 | 触发 | 场景 |
|------|------|------|
| **`send_file` 工具** | AI 主动调用 | 发送任何已有路径的文件/图片 |
| **python 自动检测** | python 执行后 | matplotlib 等生成新图片 |
| **write/edit 自动链接** | write/edit 成功后 | 创建/修改的文件 |

- **`send_file` 工具（Web 专属）**：新增 `SendFileTool` 类，仅注册到 Web 端工具注册表，CLI 不可见。AI 调用 `send_file(file_paths=['/tmp/chart.png'])` 即可向用户发送文件/图片，支持一次发送多个。图片内联显示（点击放大），文件显示下载链接
- **python 工具生成图片自动检测**：python 执行 matplotlib/PIL 等生成图片后，Web 端自动对比执行前后的图片文件快照（cwd + /tmp），发现新增图片自动作为 `display_files` 发送给前端显示
- **write/edit 写文件自动生成下载链接**：write/edit 工具成功后，Web 端自动将文件路径加入 `display_files`，前端显示文件下载链接

### 技术实现

- `ToolResult` 新增 `display_files` 字段（`[{path, filename, is_image, url, download_url}]`）
- `SendFileTool` 内联定义在 `web/server.py` 中（非独立文件），仅 Web 端 `_build_tool_registry` 注册，**CLI 工具注册表不受影响**
- python_tool.py 等工具代码**零改动**，所有检测逻辑仅在 Web 端 `server.py` 中实现
- 新增 API 端点：
  - `GET /api/files/serve_path?path=xxx` — 按绝对路径提供文件（图片内联显示）
  - `GET /api/files/download_path?path=xxx` — 按绝对路径下载文件
  - 安全限制：禁止访问 `/etc/`、`/proc/`、`/sys/`、`/dev/`、`/boot/` 目录
- SSE `tool_result` 事件新增 `display_files` 字段，前端渲染为图片网格 + 下载链接

### 用户上传文件改进（附带）

- 用户上传文件/图片的 `/api/chat/upload` 端点返回结果新增 `url` 和 `download_url` 字段
- 用户消息气泡从纯文本升级为结构化展示：图片显示缩略图（点击放大），文件显示下载链接
- 恢复历史消息时同样显示图片和文件下载链接（从消息内容中的 `[图片: xxx]` / `[文件: xxx (path)]` 标记解析生成 URL）
- 粘贴功能从仅支持图片扩展为支持任意文件类型

## 2. 死循环检测误报修复

**修改文件**：`core/loop_detector.py`

### 问题

周期震荡检测使用 `_names`（工具名序列），只看工具名不看参数。`read A → edit A → read B → edit B` 这种参数完全不同的正常交替调用，因为工具名序列 `read, edit, read, edit` 满足 p=2 周期，被误判为循环。

### 修复

将周期震荡检测从 `_names`（工具名序列）改为 `_sigs`（工具名+参数的 MD5 签名序列）。只有工具名和参数都相同的调用交替才算周期震荡。

```python
# 修复前：只看工具名
seq = list(self._names)

# 修复后：看签名（工具名+参数哈希）
seq = list(self._sigs)
```

## 3. 子 Agent 并行上限统一为 100

**修改文件**：`tools/delegate_task.py`

`MAX_TASKS` 从 10 改为 100，与 `core/subagent.py` 的 `MAX_PARALLEL_SUBAGENTS = 100` 对齐。此前 CLI 端已经是 100，但工具层的 `MAX_TASKS` 仍然是 10，导致 Web 端和 CLI 端的实际上限不一致。
