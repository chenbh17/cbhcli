# CBHCLI v5.5.6 更新日志（长会话流式卡顿根治：逐行折行缓存）

> 发布日期：2026-11-24 ｜ 上一版本：v5.5.5
> 用户明确要求发新版 v5.5.6。本版本只做一项修复（根治方案 1），
> 不含 token 计数缓存 / 上下文条降频（方案 2/3 未实施）。

## 一、症状（用户反馈）

CLI 全屏 TUI 在 **Jupyter 终端**里，单个会话运行久了、内容多了之后明显卡顿：
打字回显迟滞、滚轮/拖选不跟手、spinner 一顿一顿。会话刚开始时流畅，
内容越多越卡。

## 二、根因（源码定位 + 实测基准）

全屏渲染链路：

```
LLM 流式输出 → rich/Markdown → ScreenSink.feed() → Screen(最多5000逻辑行)
  → invalidate() → prompt_toolkit 重绘 → _main_fragments()
  → _visual_lines()【全量折行】→ 差分输出 → pty → notebook服务器 → websocket → xterm.js
```

两处随内容总量线性增长（O(N)）的全量重算，每帧都在**单线程 UI 事件循环**里跑：

1. **主因——每帧全量折行**：`shell.py` 的折行缓存键是 `(screen实例, version, width)`，
   而 `Screen.feed()` 每写一次内容 `version` 就 +1。流式期间内容一直在变 →
   缓存永远失效 → 每次重绘都把全部历史（最多 5000 行）逐字素簇重新
   `wrap_cells` + `merge_runs`（纯 Python 循环）。spinner 每 100ms、思考窗每
   0.12s 也在触发重绘，帧帧都付这个钱。本机实测（78 列、中英混合行）：

   | 屏幕内容量 | 全量折行耗时/帧 |
   |---|---|
   | 200 行 | 7.5 ms |
   | 1000 行 | 35 ms |
   | 3000 行 | 104 ms |
   | 5000 行 | 186 ms |

   每帧阻塞 100~200ms 期间，按键/鼠标事件全在排队 → 卡顿。

2. **次因——状态栏上下文条每 0.5s 全量 tiktoken 重算**（`count_messages_tokens`
   无逐条缓存）。50 万字符会话约 30ms/次。**本版本未改此项**（属方案 2）。

Jupyter 终端比原生终端更卡的原因：每个按键回显要走
`浏览器 → websocket → notebook服务器 → pty → cbhcli事件循环(正被阻塞) → 原路返回`，
服务端阻塞直接叠加成输入延迟；浏览器主线程还要解析 SGR/渲染字形。

## 三、修复（根治方案 1：逐行折行缓存）

**只改 `cbhcli_pkg/core/ui/lines.py`**，把"每帧全量折行"降为"每帧只折变过的行"：

1. 新增 `_Line(list)`：逻辑行改为带版本号的 list 子类，**任何原地变更**
   （`append` / `__setitem__` / `__delitem__` / `clear` / `extend` / `insert` /
   `pop` / `remove` / `__iadd__` / `__imul__` / `sort` / `reverse`）自动递增 `_v`。
   现有代码把行当普通 list 用，全部操作无缝兼容。
2. `Screen` 新增逐行缓存 `_wrap_cache: id(line) -> (line强引用, 行版本, 宽度, 折行结果)`。
   - **存强引用 + `is` 校验**：杜绝 line 被回收后 id 复用导致的假命中。
   - 命中条件：`ent[0] is line and ent[1] == line._v and ent[2] == width`。
   - 未变行 O(1) 复用；只有变过的行（流式期间通常就是末尾行）重折。
3. 新增 `_wrapped_line(line, width)` 单行折行入口；`visual_lines` /
   `visual_line_count` 都走它。`visual_lines` 末尾做**缓存剪枝**
   （条目数 > 行数×2+128 时按当前存活行重建），防裁剪/替换后无界增长。
4. 所有产生新行的位置（`__init__` / `_ensure_line` / 擦除 J1、J2）改用 `_Line()`。
5. **兜底**：外部塞入的普通 list（无 `_v`）不缓存、每次新鲜折行，防陈旧命中。

**语义不变**：折行/重排（T-17）、滚动缓冲上限（T-13）、覆盖/擦除（T-11）
全部保持原行为；resize 换宽度时缓存按宽度失效、自然全量重折一次。
上层 `shell.py` 的 `(screen, version, width)` 缓存无需改动——即使它每帧失效，
内层 `visual_lines` 现在也只重折变化行。

## 四、实测效果

5000 行会话、仅追加/覆盖末行的单帧折行耗时：

```
全量折行 159.9 ms/帧  →  缓存帧 0.72 ms/帧   （加速 221×）
```

流式期间 UI 事件循环不再被每帧 100~200ms 的全量折行阻塞，
Jupyter 终端里长会话打字/滚轮/拖选恢复跟手。

## 五、门禁

新增 `tests/ui/check_wrap_cache.py`（第 33 套件），覆盖：
- **正确性**：追加 / `\r` 覆盖 / `\b` / 擦除 K(0/1/2)、J(0/1/2) / 光标上移重画 /
  绝对定位 / 样式 SGR / 宽字符·emoji·ZWJ·tab / resize 多宽度 / 裁剪后追加，
  每步 `visual_lines` 与"全量新鲜折行"参照逐字符一致，`visual_line_count` 行数一致。
- **缓存命中**：monkeypatch `wrap_cells` 计数——追加单行重折 <30 行、
  无变更重折 0 行、`\r` 覆盖末行重折 ≤2 行。
- **缓存失效**：末行覆盖 / 擦除重写后结果随内容变化且与参照一致（无陈旧命中）。
- **裁剪剪枝**：`max_lines=50` 喂 200 行后缓存条目有界。
- **性能**：5000 行缓存帧 < 全量帧 ×25%。

**全部 33 套件 `/usr/bin/python3` 跑通（PASS=33 FAIL=0）。**
