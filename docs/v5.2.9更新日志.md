# CBHCLI v5.2.9 更新日志

> 发布日期: 2026-08-24
> 主题: Web 实时架构升级——WebSocket 多浏览器同步 + 会话后台运行
> + 设置页返回导航

## 一、WebSocket 实时显示（多浏览器画面一致）

旧版聊天走 SSE（POST /api/chat 持有 HTTP 流），事件只发给发起请求的那一个
浏览器，且浏览器断开/切走即丢失后续事件。v5.2.9 全面改为 **WebSocket 事件
总线**架构：

- 新增 `/ws` WebSocket 端点：客户端订阅会话后接收该会话的全部实时事件
  （流式思考/内容、工具确认、执行进度、链条调用、运行结束等）
- **多个浏览器打开同一会话，显示内容完全一致**：一个浏览器发送消息，
  其他浏览器实时看到用户消息与 AI 流式回复（已用 CDP 双页面实测验证）
- 事件按会话内单调递增 `seq` 记录到运行日志，**迟到订阅者按 `since_seq`
  回放**：新开的浏览器、断线重连都能无缝补齐，不丢事件也不重复
- 超长流保护：单次运行事件日志上限 6000 条，超出裁剪头部并通知客户端
  `resync`（重拉消息 + 按当前 seq 续订）
- 慢消费者保护：单连接发送队列积压超 5000 条自动断开（客户端重连回放恢复）
- 心跳保活：前端每 30s ping；断线自动重连（1s 起步，指数退避至 8s）

## 二、会话后台运行（切换/新建不中断）

旧版新建会话或切换会话会 `abort` 当前会话——正在执行的任务被强行终止。
v5.2.9 会话与连接彻底解耦：

- ReAct 循环改为**后台 asyncio 任务**执行（`_background_react_runner`），
  持有会话锁、逐事件发布到总线；浏览器关闭/切走/刷新均不影响执行
- **新建会话**：旧会话不中断（每轮已自动落盘），继续后台运行；
  空闲旧会话的 python 解释器会话随之清理
- **切换会话**：同 id 会话仍在内存时直接复用（保留运行状态与未落盘的
  当前轮），绝不重建副本；运行中的会话画面由事件回放接管
- 会话注册表 `_sessions_by_id`（session.id -> 会话）：全部存活会话驻留，
  上限 40 个，超出驱逐最旧的空闲会话（数据已落盘，安全）
- **侧边栏运行状态徽标**：正在后台执行的会话显示绿色"● 运行中"脉动徽标，
  由 WebSocket `session_status` 通知实时刷新（开始/完成即时更新）
- 多浏览器工具确认同步：所有订阅浏览器同时显示确认框/提问框，
  **首个应答生效**（`respond_waiting` 标志 + `responded` 事件广播，
  其他浏览器的待应答 UI 自动替换为"已在其他窗口应答"）
- 多会话并发工具执行前自动对齐进程 cwd 到会话所属工作空间
  （`_ensure_session_cwd`），后台会话不被其他会话的工作空间切换带偏
- python 工具解释器会话按聊天会话 id 隔离（原全局共享 "default"，
  并发会话变量互相污染）
- 系统提示重建按工作空间匹配（切换工作空间不再把后台会话的 cwd 提示带偏）

### 会话身份与 API
- 会话身份以 `session.id` 为准（同一 agent:model 下可并存多个会话）；
  全部聊天端点（chat/respond/abort/status/messages/load/reset/
  switch_model/compress/use-chain/off-chain）新增 `session_id` 参数，
  未传时回落到 (agent, model) 默认会话（向后兼容）
- `POST /api/chat` 立即返回 `{session_id, started}`，不再持有流
- `GET /api/chat/status|messages` 返回 `run_active`；运行中导出消息
  截断到本次运行开始处（当前运行内容由事件回放渲染，避免双份）
- 前端按浏览器持久化"上次打开的会话"（localStorage），刷新/重开页面
  自动回到同一会话；服务器重启后按 id 从历史自动找回（v5.2.8 机制保留）

## 三、设置页返回导航

  安全/索引/历史）：`← 设置`（回到设置主页）

## 五、发布当日修复（双份渲染 + CLI/Web 内存副本分叉）

用户反馈：Web 页面出现从未问过的消息（显示两遍），且最新回复不显示。
排查出两个问题并修复：

### 5.1 空闲会话订阅回放导致双份渲染（v5.2.9 引入的 bug）
事件日志在运行结束后仍保留上一轮事件（供断线重连补尾）。加载**空闲**会话
时前端从 `since_seq=0` 订阅，上一轮事件被回放在已渲染的完整消息之上——
最后一轮问答显示两遍。修复：`chatLoad`/`chatMessages`/`workspaceOpen`
响应新增 `run_seq`，前端对空闲会话按 `run_seq` 续订（跳过上一轮回放）；
运行中会话仍从 0 回放（消息已截断到运行开始处，语义不变）。

### 5.2 CLI/Web 内存副本分叉（架构盲区 + 测试污染）
CLI 与 Web 是独立进程、各自持有内存会话、共享历史文件。Web 内存中的会话
副本是某次加载时的快照：CLI 继续对话只写磁盘，Web 内存副本不更新，页面
显示过时内容（本次还叠加了开发期 CDP 测试消息注入该副本）。修复：
- 新增 `_live_session_stale_vs_disk()`：会话空闲且磁盘文件 mtime 晚于
  会话最近活动时间 1s 以上 -> 判定内存副本过期（被 CLI 等外部进程更新）
- `chatLoad` / `_load_session_core` 的"内存复用"快速路径均先做过期检测，
  过期则丢弃内存副本从磁盘重载（运行中的会话不受影响）
- 效果：CLI 对话时刷新 Web 页面即可看到最新保存内容；Web 不再显示分叉快照

> 教训：多进程共享会话文件时，"内存复用"必须校验磁盘是否被外部更新；
> 开发测试不得向真实 agent 的默认会话发送消息（应使用专用测试 agent）。

## 六、第二轮修复（5 项体验问题）

### 6.1 工具运行中可中断（重要修复）
旧版 `cs.abort` 标志只在 ReAct 轮次边界/流式轮询/等待应答时检查，
**工具执行期间**（`asyncio.to_thread(execute)` 阻塞）不响应——terminal
sleep 10 运行中点中断无效，必须等命令跑完。修复：
- `_execute_tool_interruptible()`：工具在线程执行期间，事件循环每 0.3s
  轮询 abort；触发时调用工具的 `interrupt()` 方法
- `TerminalTool.interrupt()`（新增）：`killpg` 杀掉正在运行的子进程组，
  `process.wait()` 立即返回，工具以"命令已被用户中断（进程已终止）"
  结果结束（区别于普通失败，不触发模型反思重试）
- 中断后立即结束本轮运行：记录工具结果消息 + 补全未执行工具的占位
  消息 + `aborted` 事件（跳过反思重试与剩余工具）
- 实测：terminal sleep 30 运行中中断，0.6 秒内运行结束、sh+sleep
  进程全部被杀
- 说明：python 工具代码执行无法安全杀线程，仍需等待其自然结束

### 6.2 Todo 面板后输出顺序错误
`showTodoPanel` 追加面板后未关闭当前内容块，`curContent` 仍指向面板
前的 md 元素——后续流式文字渲染到面板**上方**。修复：追加面板前先
`closeLiveReasoning()/closeLiveContent()`，之后的输出创建新块追加到
面板下方（CDP 实测 DOM 顺序正确）。

### 6.3 中断按钮仅在会话运行中显示
旧版 `state.streaming` 在切换/加载会话时不复位：浏览器 A 运行会话时，
浏览器 B 切到空闲会话后中断按钮残留。修复：`liveRunReset()` 统一
`setStreaming(false)`（切换/加载/新建/删除会话均经过它）；
`refreshStatus` 增加兜底（会话未运行却残留流式状态 -> 复位）。

### 6.4 write/edit 成功后收起卡片
旧版"成功且无 display_files 才收起"，而 write/edit 成功会自动附带
下载链接（display_files），导致卡片保持展开、代码占满屏幕。修复：
成功一律收起，**仅失败或含图片**（需直接可见）时展开；用户想看
参数/结果点击卡片标题即可。

### 6.5 侧边栏会话时间完整显示
相对时间（"3分/2天"）改为完整 `YYYY-MM-DD HH:MM:SS`（等宽小字号，
悬停有完整 title）。
