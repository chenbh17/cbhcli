# CBHCLI v4.9.7 更新日志 — 状态栏偶尔不显示修复

> 修复 CLI 输入框下方状态栏（模型/上下文/Agent/技能/路径）在 Agent 回答后偶尔不显示、按回车或 Ctrl+C 才恢复的问题。

---

## 一、问题现象

CLI 输入框下方的 `bottom_toolbar` 状态栏有时整轮不显示；按一下回车或 Ctrl+C（进入下一轮 prompt）后恢复。

## 二、根因分析（三层原因链）

### 1. prompt_toolkit 的工具栏显示门槛

`PromptSession._create_layout` 中，bottom_toolbar 容器过滤条件为：

```python
filter=Condition(lambda: self.bottom_toolbar is not None)
    & ~is_done
    & renderer_height_is_known,   # ← 高度已知才显示
```

`renderer_height_is_known` 依赖 **CPR（光标位置查询）往返**：应用启动时发送 `\x1b[6n`，终端响应后 `report_absolute_cursor_row()` 设置高度，工具栏才在重绘中出现。

### 2. CPR 请求被跳过

`Application._request_absolute_cursor_position()` 有一个前置条件：

```python
if not self.key_processor.input_queue and not self.is_done:
    self.renderer.request_absolute_cursor_position()
```

**输入队列非空时跳过 CPR 请求**。典型场景：AI 回答输出期间用户按了键（type-ahead 残留）→ 下一轮 prompt 启动时队列非空 → CPR 从未发送 → 高度永远未知 → 工具栏整轮被过滤器隐藏。

### 3. "按键后恢复"的原因

回车/Ctrl+C 会结束当前 prompt（提交空输入/键盘中断），主循环再次调用 `prompt()` 创建全新 Application——此时队列已空，CPR 正常往返，工具栏恢复显示。

## 三、修复方案

新增 `install_toolbar_display_fix()`（input_box.py，导入时安装）：

将 `prompt_toolkit.shortcuts.prompt` 模块命名空间中的 `renderer_height_is_known` 引用替换为恒真 `Condition`，工具栏**首轮渲染即显示**，不再等待 CPR。

**安全性**：`renderer.render()` 在高度未知时按 `height = max(0, last_height, preferred_height)` 绘制，布局按优选高度分配行（提示符行+工具栏行），位置正确；CPR 响应到达后的高度校正逻辑与原生一致。对 CPR 不支持的终端还顺带修复了工具栏永不显示的问题。

## 四、踩坑：补丁第一版无效

首版用 `import prompt_toolkit.shortcuts.prompt as m` 获取模块后打补丁，验证发现工具栏过滤器未变。排查发现：

- `prompt_toolkit/shortcuts/__init__.py` 中 `from .prompt import prompt` 把导出的 **`prompt()` 函数绑定为包属性**，遮蔽了同名子模块
- `import prompt_toolkit.shortcuts.prompt as m` 的 `as` 绑定通过 `getattr(shortcuts, 'prompt')` 解析 → 拿到的是**函数对象**而非模块
- 补丁打在了函数对象的属性上，真实模块（`sys.modules['prompt_toolkit.shortcuts.prompt']`）未被修改

**正确做法**：通过 `sys.modules['prompt_toolkit.shortcuts.prompt']`（或 `PromptSession.__module__`）获取真实模块对象再打补丁。已验证布局树中 bottom_toolbar 容器过滤器确实包含恒真条件。

## 五、影响文件
