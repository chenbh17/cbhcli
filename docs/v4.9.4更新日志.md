# CBHCLI v4.9.4 更新日志 — Web 界面全面重构

> 本次更新**完全重写 Web 端**（后端 `web/server.py` + 前端全部静态资源），对标 CLI 全部功能与逻辑，修复大量 bug，界面全面重设计。启动命令不变：`cbhcli web`。

## 一、后端重构（web/server.py 全部重写）

### 1. 架构升级：WebChatSession 统一会话封装

旧版问题：会话创建逻辑在 `/api/chat` 和 `/api/chat/load` 中**重复两份且不一致** —— `/api/chat/load` 恢复的会话**漏初始化上下文压缩组件、token_counter、abort 标志**，导致历史会话恢复后自动压缩失效、状态统计不准。

新版统一为 `WebChatSession` 类，一处创建处处可用：

```python
WebChatSession.create(agent_name, model_name)
  ├─ Session / LLMClient / token_counter
  ├─ _build_tool_registry()（16内置 + 13 cbhpacks + 知识库/记忆/子Agent）
  ├─ MCPManager（真实连接 + 工具注册）
  ├─ SkillManager + 系统提示构建
  ├─ ContextCompressor + ContextWindow（含 tools_schema_tokens 精确计算）
  ├─ asyncio.Queue（应答）+ asyncio.Lock（并发互斥）
  ├─ rebuild_tools_sync()（工具开关/MCP 变更后同步活跃会话）
  ├─ usage_stats()（token 精确统计）
  └─ export_messages()（前端刷新后恢复对话）
```

### 2. ReAct 循环与 CLI 完全对齐

| 能力 | 旧版 | 新版 |
|------|------|------|
| 自我反思重试（MAX_REFLECTION_RETRIES=10） | ❌ 无 | ✅ 与 ai_handler 一致的反思提示注入 + SSE `reflection` 事件 |
| 工具调用去重 + 模糊名解析 | ❌ | ✅ 按 (resolved, args_json) 去重 |
| ReAct 循环内自动压缩 | ✅ | ✅（线程池执行避免阻塞） |
| 主模型失败切换备用模型 | ✅ | ✅（重写为独立 `_stream_round` 生成器） |
| 工具执行 | 同步阻塞事件循环 | ✅ `asyncio.to_thread` 线程池执行 |
| 中断响应 | 流式期间不检查 abort | ✅ 0.5s 轮询，流式/确认/ask_user 等待中均可中断 |

### 3. 关键 bug 修复

1. **`/api/chat/load` 恢复会话缺少压缩组件** — 统一走 `WebChatSession.create` 后修复
2. **确认等待中点中断仍执行工具** — 旧 `chat_abort` 向应答队列投放空串 `""`，被 `_react_loop` 误判为"非 n 即确认"继续执行工具。改为只置 abort 标志（`wait_response` 0.5s 轮询感知），实测中断后工具不再执行
3. **工具执行阻塞整个事件循环** — `registry.execute` 改 `asyncio.to_thread`，长命令执行期间其他 API 不再卡死
4. **token 估算粗糙** — 旧版"4字符=1token"估算，改用 `token_counter.count_messages_tokens` 精确计算（含消息结构开销）
5. **MCP refresh 是假的** — 旧版只校验配置返回"下次 CLI 会话生效"。新版全部走真实 `MCPManager`：`add_server/remove_server/refresh_server/toggle_tool/get_all_server_tools` 均真实连接生效，并通过 `rebuild_tools_sync()` 同步到该 Agent 所有活跃聊天会话
6. **工具开关即时生效** — `/api/agents/{a}/tools/{t}` 切换后同步 `set_disabled_tools` 到所有活跃会话（旧版需重启）
7. **会话并发冲突** — 同一会话并发流式请求返回 409 而非互相污染
8. **嵌入/重排序模型配置变更后向量库不重建** — 新增 `_reset_vector_store()` 懒重建
9. **Agent 文件（soul/memory/tools/usage）编辑后不生效** — 保存后自动刷新活跃会话系统提示

## 附录 B：稳定性修复包（v4.9.4 内，未改版本号）

1. **Todo 工具渲染崩溃导致任务中断** — 模型传非数组 todos 时 `todos.map is not a function`，异常传播杀死整个 SSE 消费循环（后续事件全部丢失，任务看似"卡住"）。双重修复：
   - **事件处理器隔离**：每个 SSE 事件处理包 try/catch，单个事件异常不再中断流
   - **`normalizeTodos()` 防御解析**：兼容 JSON 字符串/嵌套对象/字符串项/非数组等各种模型异常传参
2. **Todo 展示改版** — 不再用可折叠工具卡片（需展开才能看），改为**任务面板**：蓝框独立面板直接展示全部任务事项（✓完成划线 / ◐进行中高亮 / ○待办 + 完成计数徽章），随 Todo 调用实时原位更新；历史会话恢复同样渲染面板
3. **复制按钮远程访问失效** — `navigator.clipboard.writeText` 仅在安全上下文（https/localhost）可用，远程 HTTP 访问（如 `http://内网IP:18888`）时 clipboard API 未定义导致复制静默失败。新增 `copyText()`：安全上下文走 clipboard API，否则回退 `execCommand("copy")`（临时 textarea 方案），并带失败反馈

## 附录 D：温度配置 / 子Agent并发 / edit 工具（v4.9.4 内，未改版本号）

1. **模型温度配置丢失修复** — web 端 `ModelConfig` 缺少 `temperature` 字段，在 web UI 编辑模型会静默丢弃模型专属温度（导致 kimi-k3 等强制 temperature=1 的模型在 image 工具调用时发送默认 0.1 而 400 报错）。修复：
   - `ModelConfig` 增加 `temperature: Optional[float]`，add/update 用 `model_dump(exclude_none=True)`
   - 模型表单新增温度输入（0-2，留空用全局 0.1，预填当前值）
   - **CLI 温度逻辑验证为正确**：`LLMClient._get_temperature()` 保证模型配置温度永远优先于调用方默认值，image 工具硬编码的 0.1 会被模型配置（如 1.0）覆盖（已实测 API 调用成功）

5. **image 工具视觉模型名称匹配 bug（kimi-k3 温度报错的真正根因）** — `_find_vision_models()` 优先级 1 用 `llm_client.model_name`（API 模型 ID，如 `"kimi-k3"`）与配置 `name` 字段（如 `"Kimi-K3"`）直接相等比较，大小写/命名差异导致**永远失配**，落入 else 分支用 client 信息构建**不含 temperature 的合成配置** → LLMClient 无温度覆盖 → 发送默认 0.1 → Moonshot 400。报错信息中显示小写 `'kimi-k3'`（模型 ID）正是走了合成配置分支的铁证。修复：按 `name` 或 `model` 字段忽略大小写匹配；else 分支继承 `llm_client.model_temperature`。已用真实图片端到端验证识别成功
2. **子Agent 最大并发 10 → 100** — `subagent.py MAX_PARALLEL_SUBAGENTS=100`，`delegate_task` 工具描述/参数说明同步更新
3. **edit 工具空白字符宽容匹配** — 文件含非断行空格(U+00A0)而 old_str 用普通空格（或反之）时精确匹配失败报"未找到匹配的文本"。新增 `_find_flex_spans()`：old_str 中空格类字符（U+0020/U+00A0/U+2007/U+202F）编译为等价字符类正则兜底匹配，按区间替换保留文件原始空白；成功时提示"已使用空白字符宽容匹配"
4. **edit diff 行内字符级高亮（web + CLI 双端）** —
   - **web 前端** diffBlockEl 重写：公共前缀/后缀行渲染为无底色上下文；中间变更区行数一致时逐行做公共前后缀字符对比，**仅差异段加红/绿底色**（`.diff-hl-del`/`.diff-hl-add`），未变更部分保持原底色
   - **CLI** `_render_edit_preview` 新增 `_edit_inline_marks()`：同样的行内对比算法，差异段用 `Text.stylize` 叠加亮一档底色（DEL `bold on #7a2626` / ADD `bold on #267a26`，256 色终端自动降采样为 88/28），列底色保留暗色
   - **修复 IndexError**：宽屏并排模式下 new_lines 比 old_lines 长时 `old_marks[i]` 越界崩溃（新增 `_marks()` 越界返回空标记）
