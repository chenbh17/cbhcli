## 一、新增功能

### 1. image 图片识别工具

当主模型不支持视觉功能时，AI 可通过 `image` 工具调用已配置的视觉模型识别图片内容，返回识别结果给主模型。支持同时识别多张图片。

**工作流程**：
```
用户请求 → 主模型（非视觉）通过 Function Calling 调用 image 工具
  → image 工具自动查找已配置的视觉模型
  → 将图片编码为 base64，构建 OpenAI 多模态消息格式
  → 调用视觉模型识别图片
  → 返回识别结果给主模型
```

**工具参数**：
- `image_paths`（必填）：图片路径列表，支持绝对路径和 `~` 路径
- `prompt`（必填）：识别需求描述，如"描述这张图片的内容"或"提取图片中的文字"

**视觉模型选择优先级**：
1. 当前 Agent 使用的模型（如果它支持视觉）
2. `/fallback vision` 配置的备用视觉模型（按顺序）
3. 其他已配置的支持视觉的模型

**视觉模型 fallback**：当第一个视觉模型调用失败（断网、API异常等）时，自动按顺序尝试下一个备用视觉模型，直到成功或全部失败。

**工具调用显示**：
- `● image` 行显示图片数量、路径和识别需求（截断200字符）
- 确认前显示绿色背景的预览区块，列出所有图片路径和识别需求
- 执行后只显示识别结果摘要

### 2. /fallback 备用模型管理命令

当主模型断网或异常时，自动切换到备用模型继续任务。视觉模型同理。

**命令列表**：
| 命令 | 功能 |
|------|------|
| `/fallback list` | 查看备用模型配置 |
| `/fallback add main <模型名>` | 添加主模型备用 |
| `/fallback add vision <模型名>` | 添加视觉模型备用 |
| `/fallback rm [main\|vision] <模型名>` | 移除备用模型 |
| `/fallback reorder [main\|vision]` | 交互式重新排序备用模型 |
| `/fallback clear [main\|vision]` | 清空备用模型列表 |

**主模型 fallback 机制**：
- 在 ReAct 循环的每一轮，先尝试主模型
- 主模型异常（网络错误、API非200、超时等）时，按 `/fallback main` 配置的顺序依次尝试备用模型
- 每轮都先试主模型，失败才降级到备用（主模型恢复后自动回到主模型）
- `KeyboardInterrupt`（Ctrl+C）不触发 fallback，直接中断

**视觉模型 fallback 机制**：
- image 工具执行时，按优先级顺序依次尝试视觉模型
- 第一个模型失败（网络错误、API非200等）时自动切换到下一个
- 直到成功或全部失败

**配置存储**：`~/.cbhcli/config.json` 中新增两个字段：
- `fallback_models`：主模型备用顺序（模型名称列表）
- `fallback_vision_models`：视觉模型备用顺序（模型名称列表）

## 二、新建文件（2个）

### 1. `cbhcli_pkg/tools/image.py`（269行）

图片识别工具，继承 `BaseTool`。

**类**：`ImageTool(BaseTool)`
- `__init__(self, app)`：接收 CBHCLIApp 实例，用于获取全局配置中的视觉模型
- `name` → `"image"`
- `description` → 使用视觉模型识别图片内容
- `parameters` → `image_paths`（数组）+ `prompt`（字符串）
- `execute(image_paths, prompt)` → 加载图片base64 → 依次尝试视觉模型 → 返回识别结果
- `_find_vision_models()` → 按优先级返回视觉模型列表（当前Agent模型 → fallback vision → 其他视觉模型）
- `_call_vision_model(model_config, images, prompt)` → 创建 LLMClient，构建多模态消息，调用 `client.chat()` 非流式获取响应

### 2. `cbhcli_pkg/commands/fallback_cmd.py`（251行）

备用模型管理命令模块。

**函数**：
- `register_fallback_commands(parser, app)`：注册 `/fallback` 命令
- `_list_fallback(app)`：列出主模型和视觉模型的备用配置
- `_add_fallback(app, category, model_name)`：添加备用模型（检查模型存在性、视觉模型检查vision标记）
- `_rm_fallback(app, category, model_name)`：移除备用模型
- `_reorder_fallback(app, category)`：交互式重新排序（输入编号顺序）
- `_clear_fallback(app, category)`：清空备用列表
- `_validate_category(category)`：验证类别参数（main/vision）
