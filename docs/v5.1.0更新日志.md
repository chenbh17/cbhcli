# v5.1.0 更新日志 - Agent 链条（多 Agent 调用编排）

## 概述

v5.1.0 新增**用户 Agent 调用链条（Agent Chain）**功能：定义多层级 Agent 调用链，元 Agent 通过 `call_agent` 工具按链条拓扑调用下游用户 Agent（各自以完整身份执行），实现跨 Agent 工作流。新增 3 个文件，修改 16 个文件，同步批量更新 13 个现有 Agent 工作空间文档。

---

## 新增文件

### 文件 1：`cbhcli_pkg/core/agent_chain.py`（~645行）

链条核心模块，包含：

| 组件 | 功能 |
|------|------|
| `ChainAgent` | 链条中一个 Agent 节点（name + call_instruction） |
| `ChainLevel` | 链条中的一个层级（level + agents 列表） |
| `AgentChain` | 完整链条（name/description/levels），含上下游查询、校验方法 |
| `ChainManager` | CRUD + 持久化到 `~/.cbhcli/agent_chains.json` |
| `ChainExecutor` | 下游 Agent 调用执行器：加载目标 Agent 完整配置（AgentConfig + AgentPersona + SkillManager + MCPManager）→ 构建独立 Session + 工具注册表（按 disabled_tools 过滤）→ 挂载 Harness 组件（HookManager/CheckpointManager/Tracer，权限共享）→ AIHandler 执行 ReAct 循环 → 回传结果 |
| `build_chain_prompt()` | 构建注入到上游 Agent 系统提示的链条信息文本（含下游 Agent description 实时读取 + call_instruction） |
| `render_chain_tree()` | 渲染链条树形结构（├─ └─ 连接线） |

**关键设计**：
- `ChainExecutor` 为下游 Agent 创建独立 `ToolRegistry`（含 `call_agent` 如有更下游）+ 独立 `ToolExecutor`（共享 `PermissionEngine`，下游自己的 HookManager/CheckpointManager/Tracer）
- 权限继承：CLI 端不设 `no_more_confirmations`（标准模式危险操作仍交互确认）；Web 端设 `no_more_confirmations = True`（线程中无法交互）
- 下游 Agent 的 `AIHandler` 用 `display_label=f"[{target_agent}] "` 显示 Agent 名称

### 文件 2：`cbhcli_pkg/tools/call_agent.py`（~131行）

`call_agent` 工具，仅在链条绑定时注册。校验目标 Agent 是否为当前 Agent 的合法下游，调用 `ChainExecutor.execute()` 执行，返回下游 Agent 的最终回复。

### 文件 3：`cbhcli_pkg/commands/chain_cmd.py`（~721行）

`/chain` 命令，8 个子命令全部支持**无参数进入交互式引导**：

| 子命令 | 功能 |
|--------|------|
| `list` | 树形展示所有链条（含调用说明摘要） |
| `add` | 交互式创建：引导输入名称 → 逐层编号选择 Agent → 填写调用说明 |
| `rm` | 从列表编号选择要删除的链条 |
| `use` | 从列表编号选择要激活的链条（校验元 Agent 匹配） |
| `off` | 取消链条绑定 |
| `show` | 从列表编号选择查看详情（含 Agent 描述+模型+调用说明） |
| `config` | 从列表编号选择进入循环编辑模式（修改描述/调用说明/增删层级/替换 Agent） |
| `rename` | 从列表编号选择后输入新名称 |

**交互设计**：
- `_select_chain()`：链条列表编号选择（显示名称+描述+激活状态）
- `_select_agents()`：Agent 编号选择（非手动输入名称），支持多选和范围语法 `1-3`
- config 循环编辑模式：每次操作后询问"继续编辑?"
- config 描述/调用说明修改：`ask_text_or_none` 回车返回 `""`（非 `None`），单独处理为跳过；`'clear'` 清空

新增链条激活状态持久化方法（per-agent 存储到 `config.json`）：

```python
def get_active_chain(self, agent_name: str) -> Optional[str]:
    return self.config.get("agents", {}).get("active_chains", {}).get(agent_name)

def set_active_chain(self, agent_name: str, chain_name: Optional[str]) -> None:
    chains = self.config.setdefault("agents", {}).setdefault("active_chains", {})
    if chain_name:
        chains[agent_name] = chain_name
    else:
        chains.pop(agent_name, None)
    self.save()
```

## 踩坑记录

1. **`ask_text_or_none` 回车返回 `""` 非 `None`**：config 修改描述时，提示"回车跳过"但实际清空了描述。根因：`ask_text_or_none` 回车返回空字符串 `""`（只有 Ctrl+C/Esc 才返回 `None`），`if new_desc is not None:` 判断通过。修复：增加 `elif new_desc == "":` 分支单独处理为跳过。

2. **`onclick: close` 引用 TDZ 中的 `const` 变量**：`const { close } = openModal({footer: [el("button", {onclick: close}, ...)]})` 中，`close` 在 `openModal` 返回前不存在（temporal dead zone），报 `ReferenceError: Cannot access 'close' before initialization`。修复：改为 `onclick: () => close()` 闭包延迟访问。

3. **FastAPI `req.body()` 是 coroutine**：链条 API 端点定义为 `def`（同步），但 `req.body()` 返回 coroutine 需要 `await`。报 `TypeError: not coroutine`。修复：全部改为 `async def` + `await req.body()`。

4. **`_WebAgentContext` 属性不全导致 `call_agent` 报错**：`ChainExecutor` 访问 `self._app.agent_manager`/`global_config`/`permission_engine`/`tracer`，但 `_WebAgentContext` 只有部分属性。修复：补全全部属性 + `WebChatSession.create` 中设置 + `ChainExecutor` 用 `getattr` 安全访问。

5. **Web 链条激活状态不保留**：两个原因——(a) `use-chain`/`off-chain` API 未持久化到 `GlobalConfig`；(b) `chat_status` 在 session 不存在时（刷新页面后）不返回链条状态。修复：API 端点持久化 + `WebChatSession.create` 恢复 + `chat_status` 从 config 读取。

6. **Web 任何 Agent 都能激活链条**：`use-chain` API 无元 Agent 校验。修复：API 端点校验 `agent_name == chain.get_root_agent()`；前端 `showChainPicker` 只显示当前 Agent 是元 Agent 的链条。

7. **文件包含非断行空格 U+00A0**：`app.js` 中一处 U+00A0 导致 edit 工具无法匹配文本。修复：先全局清理 U+00A0 为普通空格再编辑。

8. **`refreshStatus` 未 await 导致状态不同步**：`onAgentChange` 中 `refreshStatus()` 是 async 但未 await，`updateChainIndicator()` 用旧状态。修复：先清空 `state.activeChain`，await `refreshStatus()` 后再更新。
