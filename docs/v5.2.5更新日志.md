# CBHCLI v5.2.5 更新日志

**日期**: 2026-08-14
**主题**: 新增 `cbhcli exec` 一次性非交互执行入口（headless 模式）--对标 `claude -p` / `codex exec`

## 功能概述

在终端一次性下发任务 -> AI 自动完成 ReAct 工具调用循环 -> 结果输出到 stdout -> 进程退出。
不进入交互式聊天界面，用于 shell 脚本、CI/CD、管道集成。

```bash
cbhcli exec [选项] [PROMPT]
echo "任务..." | cbhcli exec -q
cbhcli exec --agent xxx --model xxx --mode yolo "任务..."
cbhcli exec -c "继续上次任务"
cbhcli exec --output-format json "任务..." | jq .result
```

## CLI 参数

| 参数 | 说明 | 默认 |
|------|------|------|
| PROMPT（位置参数） | 任务描述；缺省且 stdin 非 TTY 时自动读 stdin；`-` 显式读 stdin | - |
| --agent NAME | 使用指定 Agent（不存在则报错并列出可用 Agent） | 上次激活的 Agent |
| --model NAME | 本次临时使用指定模型（原地切换组件，不写持久化配置） | Agent 当前模型 |
| --mode readonly/standard/auto/yolo | 权限模式 | **yolo（零确认）** |
| --max-turns N | ReAct 循环最大轮次保护 | 999 |
| --output-format text/json | text=只输出最终回答；json=输出结构化结果（result/session_id/agent/model/rounds/usage/exit_reason） | text |
| --continue, -c | 续接该 Agent 最近一次历史会话后执行 | 关 |
| --resume SESSION_ID | 恢复指定历史会话后执行（会话ID或文件名前缀） | - |
| --no-save | 本次会话不写入 history | 保存 |
| --cwd PATH | 启动前切换到指定工作目录 | 当前目录 |

**退出码**：0=成功 | 1=执行错误（模型未配置/API失败/Agent不存在/max_turns/loop_break）| 2=用法错误或权限拒绝 | 130=用户中断

## 技术实现

### 1. 新增文件 `core/exec_runner.py`（380 行）

`run_exec(args) -> int` 承载全部 headless 逻辑，cli.py 保持轻量。

### 2. cli.py 入口分发（基于原始 argv）

exec 分发在顶层 parser 之前基于 `sys.argv[1][0] == 'exec'` 直接路由，
绕过顶层 parser 对 `-h`/`-v` 的抢先消费（否则 `cbhcli exec -h` 会打印主帮助而非 exec 帮助）。
`web` 子命令保持原有分发逻辑不变。

### 3. 复用 CBHCLIApp，跳过交互主循环

- 构造 `CBHCLIApp()`（全套组件自动初始化），**不调用 `app.run()`**；
- `--agent` 时 `app._load_agent(name, do_index=False)`；
- `--model` 时 `global_config.get_model(name)` -> `app.switch_model(cfg)` 原地切换（仅进程内）；
- `app.set_permission_mode(mode)`（系统提示注入自动生效）；
- 调 `app._handle_ai_request(prompt)` **复用压缩检查 + UserPromptSubmit/Stop 钩子链**；
- 结束后仿 `run()` 的 quit 逻辑保存会话（`--no-save` 跳过），供 `-c`/`--resume` 续接。

### 4. stdout/stderr 分离（fd 级重定向）

`os.dup2` 把 fd1 重定向到 fd2（`-q` 时到 devnull），覆盖一切经 stdout 的输出
（print / rich Console / 子进程继承），**stdout 管道里只有最终结果**；
`--output-format json` 输出单条 JSON（rounds/usage 按恢复会话基线的差值统计）。

### 5. 非交互适配（运行时补丁，全部仅本进程生效，零修改核心文件本体）

| 补丁 | 机制 |
|------|------|
| 捕获最终回复 | 包装 `AIHandler.process_request`（`_handle_ai_request` 不透传返回值） |
| 轮次上限 | `ai_handler.MAX_TOOL_ROUNDS` 模块属性按 `--max-turns` 覆盖 |
| 思考显示禁用 | 包装 `ThinkingDisplay.__init__` -> `enabled=False`（ANSI 原地重绘序列不进日志） |
| 动画禁用 | `tool_executor.animations_enabled=False`（Spinner 另有 isatty 自检，双保险） |
| yolo 零确认 | `tool_executor.no_more_confirmations=True`（Web 端同款机制） |
| 非 yolo 确认拒绝 | 包装 `execute_with_display` 预检 `permission_engine.check()==ASK` -> 返回 ToolResult("非交互模式(exec)下该操作需要人工确认...请改用 --mode yolo")，禁止终端确认等待 |
| ask_user 禁用 | 注册表 disabled_tools **增量添加**（当前集合 ∪ {ask_user}，不整体覆盖避免误动用户手动禁用项）-> `get_openai_tools()` 不返回（LLM 不可见）+ `execute()` 层拒绝，双保险 |
| 权限拒绝统计 | `tool_executor.on_tool_execute` 回调监测 error 关键词 -> exit_reason=permission_denied / 退出码 2 |

### 6. 会话续接（--continue / --resume）

`-c` 取该 Agent 最近一次历史会话；`--resume` 按会话 ID/文件名匹配。
原地恢复对齐 `/resume`（v5.2.3 语义）：保留当前首条主系统提示（最新 skills/tools/memory），
跳过旧主提示、**保留 `[历史对话摘要]`**；恢复后沿用历史会话 ID，多轮 `-c`/`--resume` 串联同 ID。

6. ✅ `--no-save` -> history 文件数不变（453 -> 453）
7. ✅ 回归：`cbhcli -v` / `cbhcli -h` / `cbhcli web -h` / `cbhcli exec -h` / 交互模式不受影响
8. ✅ headless 全程 LLM 工具列表不含 ask_user（17 工具实测验证），执行层同时拒绝；

## 设计约束（全部遵守）

- 不修改 `run()` 交互主循环，`cbhcli`（无参）与 `cbhcli web` 零影响；
- 不动 Web/Jupyter 复用的核心路径（所有补丁均为 exec 进程内运行时 monkey-patch）；
- 全局配置/Agent/权限规则文件只读使用（--mode/--model 仅进程内生效）；
- 零新增依赖。

| `--verbose, -v` | 显示过程输出（工具执行/思考过程实时走 stderr）；**默认静音，stdout 只含最终结果（管道友好）** | 关 |

## 补丁（同日）：默认静音 + 修复 verbose 终端重复输出

**问题**：非 quiet 模式下终端直接运行时 AI 回答显示两遍--第一遍是流式渲染（fd 重定向后走 stderr），第二遍是 exec 退出前 print(result) 到 stdout，终端同屏两次都可见。

**修复（按用户决策）**：
1. **`--quiet/-q` 移除，语义反转为 `--verbose/-v`**：exec 本身就是 headless 入口，默认即静音（fd1->devnull，stdout 只有一次最终结果）；需看过程显式 `-v`（fd1->stderr 实时可见）。
2. **verbose + stdout 为 TTY 时跳过最终回答的 stdout 打印**（终端已从 stderr 看到完整流式回答，再打印 result 会重复）；verbose + stdout 为管道时仍打印（消费者等结果）。json 模式不受影响（始终输出）。
3. 同步范围：cli.py（参数+print_help）/ exec_runner.py / README / agent.py 模板 / 14 个现有 Agent usage.md。
