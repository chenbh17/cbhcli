## 二、terminal 工具"无限等待"修复（补丁）

### 问题现象
部分命令"实际已完成"却空等到 30 秒超时才返回：`cbhcli`(REPL)、`nohup xxx &`、守护进程等。

### 根因（两类）
- **A. 进程本身不退出**（cbhcli/vim/top 等 REPL/交互程序）→ 只能等超时 kill
- **B. 主进程已退出但管道无 EOF**（nohup/&/守护进程的孙进程持有 stdout/stderr 管道写端）→ 旧实现 `communicate(timeout)` 同时等"进程退出+管道EOF"，空等满超时

### 修复方案（terminal.py 重写）
1. `process.wait(timeout)` 替代 `communicate(timeout)` —— 只等主进程退出，**不等管道 EOF**
2. **后台读线程持续 drain 两个管道**（`_pipe_reader` 逐块 `os.read(fd,4096)`）：
   - 防止 >64KB 输出撑爆管道缓冲导致主进程阻塞（wait 期间没人读会死锁）
   - 逐块读而非 read()：孙进程持有写端时 read() 永阻塞且已读数据不返回；逐块读 join 超时放弃时已读数据不丢
3. 主进程退出后 `join(1.0)` 收残余输出；孙进程仍持有写端 → daemon 线程直接放弃
4. **start_new_session=True + `os.killpg(pid, SIGKILL)`**：超时杀整个进程组（旧实现只 kill shell，子进程变孤儿继续持有管道，join 空等1秒×2）；killpg 后管道立即 EOF，超时返回从 5s→3s
5. **stdin 保持继承父进程**：sudo 密码通过 /dev/tty 与用户直接交互（不经管道），交互能力保留，不一刀切禁交互
6. description 警告 AI 避免 REPL 类命令（cbhcli/vim/nano/top/htop/less/ssh/无参 python/bash），并说明 sudo 密码支持
7. schema 新增 `timeout` 参数（AI 可调，默认30）

### 测试结论

| 场景 | 旧实现 | 新实现 |
|------|--------|--------|
| nohup xxx & | 空等30s超时 | 0.0s 立即返回 |
| 孙进程持管道(fork后父退) | 空等到超时 | 0.1s 返回 |
| 超时 kill(sleep 10,t=3) | 5s(孤儿残留) | 3s(killpg 无泄漏) |
| 大输出 seq 200000 | 正常 | 0.0s 无死锁 |
| sudo 密码 | 可用(/dev/tty) | 可用(不变) |

### 关键经验
- **communicate() vs wait()**：前者等"进程退出+管道EOF"，后者只等进程退出；有孙进程持管道的场景必须用 wait
- **wait 期间必须持续读管道**，否则输出>64KB 时主进程阻塞在 write 死锁
- **读线程用逐块 os.read 而非 read()**：孙进程持写端时 read() 连已缓冲数据都不返回
- **shell=True 的 kill 只杀 shell**：子进程需 start_new_session+killpg 杀整组
- sudo 走 /dev/tty 不依赖 stdin/管道，继承 stdin 即可保留交互

## 三、ask_user 工具两个 bug 修复（补丁）

### Bug 1: 选"自定义输入"报错 `ask_text() missing 1 required positional argument: 'prompt'`
- **根因**：v4.9.0 从内置 input() 迁移到 prompt_toolkit 时的漏网之鱼。内置 input() 可无参调用，但 ask_text(prompt) 的 prompt 必填。共 3 处无参调用：ask_user.py:135、skills_cmd.py:115/143（多行输入循环）
- **修复**：prompt_utils.py 中 `ask_text(prompt="")` / `ask_text_or_none(prompt="")` 的 prompt 改为可选（默认""），一次修复全部 3 处调用点，符合 input() 语义
- **附加清理**：ask_user.py 自定义输入分支合并为 `ask_text(f"\n{_C_AI_HINT}请输入你的回答: {_C_RESET}")`（删掉 print+end=''）

### Bug 2: prompt 中 ANSI 颜色码显示为字面乱码 `^[[34m请选择: ^[[0m`
- **根因**：prompt_utils 用 `[('class:prompt', prompt)]` 元组传 prompt，prompt_toolkit 不解析字符串内的 ANSI 转义序列，ESC 字节被渲染为 caret 可见形式 `^[`
- **修复**：prompt_utils 新增 `_to_formatted(prompt)`：检测到 `\033[` 时用 `prompt_toolkit.formatted_text.ANSI(prompt)` 包装（ANSI 类会解析转义序列为样式）；普通文本保持 class:prompt 青色样式；空串返回 ""
- **影响面**：仅 ask_user.py:91 一处传了 ANSI prompt，但 _to_formatted 对未来所有调用方通用

### 关键经验
- **从 input() 迁移到自定义 ask_text 时，无参调用点必须全局 grep 检查**（`ask_text()` 模式），v4.9.0 漏了 3 处
- **prompt_toolkit 元组 formatted text 不解析 ANSI 码**：`[('class:x', '\033[31m红\033[0m')]` 会显示乱码；需用 `ANSI()` 包装或直接用样式类
- **测试 ask_user 等工具前先 `import cbhcli_pkg.core`**：ask_user.py 顶层 import core.prompt_utils 会触发 core/__init__ → app.py → 又 import ask_user，从 ask_user 起手的导入顺序会循环导入报错（正常运行路径无此问题）
- 非 TTY 测试 prompt_toolkit：`printf '答案\n' | python3 ...` 管道喂输入可行，会打印 "Warning: Input is not a terminal" 但功能正常

## 四、Ctrl+C 不终止子进程修复（补丁）

### 问题
start_new_session=True（killpg 修复引入）的副作用：shell 子进程独立成进程组，Ctrl+C 的 SIGINT 只发给 cbhcli 前台进程组，子进程收不到 → cbhcli 中断回到输入框，但子进程（如 sleep 100）变孤儿继续运行。

### Ctrl+C 完整链路（修复后）
1. Ctrl+C → SIGINT 发给 cbhcli 前台进程组 → Python 抛 KeyboardInterrupt
2. terminal.execute() 显式捕获 KeyboardInterrupt → `_kill_process_group()` killpg 杀子进程组 → process.wait() → **re-raise**
3. 传播：tool_executor → ai_handler(`except KeyboardInterrupt: raise`) → app.py 主循环捕获 → 打印"操作被中断"回到输入框
4. python 工具的 exec 在 cbhcli 进程内执行，SIGINT 直接中断，无子进程问题

### 修复内容
- terminal.py 新增 `_kill_process_group(process)` helper（killpg 失败回退 process.kill()），超时与 Ctrl+C 两路径共用
- execute() 的 wait 新增 `except KeyboardInterrupt` 分支：killpg + wait + join(1s) + raise

### 关键经验
- **start_new_session/killpg 与 Ctrl+C 的矛盾**：要超时杀得干净（killpg），就必须显式处理 Ctrl+C（子进程收不到 SIGINT）
- **except Exception 不捕获 KeyboardInterrupt**（继承 BaseException），工具内的 KeyboardInterrupt 会穿透到 app 主循环
- **测试脚本验证 SIGINT**：`threading.Timer(1, os.kill(os.getpid(), signal.SIGINT))` 可模拟 Ctrl+C；pgrep 检查孤儿时需注意旧测试残留会干扰，先 pkill 清理

## 五、ask_user 取消语义修复（补丁）

### 问题
用户在 ask_user 按 Esc/Ctrl+C 取消时，返回"用户未输入选择"而非"用户取消了回答"。

### 根因
`ask_text()` 内部 `except (EOFError, KeyboardInterrupt): return default`——**把取消异常吞掉返回 default("")**，调用方的 except 分支永远触发不了，"取消"与"空回车"都变成空字符串无法区分。

### 修复（2个文件）
1. **ask_user.py**：两处输入（选择/自定义输入）改用 `ask_text_or_none`（None=取消，""=空输入，语义可区分）；except 分支改为 `if choice is None` 判断
2. **prompt_utils.py**：共享 _session 加 Esc 键绑定 `@kb.add('escape') → event.app.exit(exception=KeyboardInterrupt)`（prompt_toolkit 默认 Esc 是 meta 前缀键不取消；单行提问场景 Esc 无其他用途，绑定为取消）

### 语义对照表（修复后）

| 用户操作 | ask_text_or_none 返回 | ask_user 报错 |
|----------|----------------------|----------------|
| Esc / Ctrl+C / Ctrl+D | None | "用户取消了回答/输入" |
| 直接回车（空输入） | "" | "用户未输入选择" |
| 正常输入 | 输入内容 | 正常流程 |

### 关键经验
- **ask_text vs ask_text_or_none 的选择**：取消需要与空输入区分时必须用 or_none 版；ask_text 吞异常返 default 只适合"取消=用默认值"场景（如 /model add 各字段）
- **prompt_toolkit Esc 默认不取消**，需 KeyBindings 显式绑定 `event.app.exit(exception=KeyboardInterrupt)`
- 非TTY测试：Ctrl+C 用 `threading.Timer + os.kill(getpid(), SIGINT)` 模拟；Ctrl+D 用 printf 管道输入行数不足触发 EOF

## 六、后台任务管理系统（process/kill_process 工具，补丁）

### 设计背景
terminal 超时(默认30s) kill 会误杀 pip install 大包等长任务。用户决策：python 工具不改，只改 terminal。

### 架构
```
terminal 超时 → 不 kill，注册 ProcessManager 为后台任务 → 提示 AI 调 process
                  ↓
        process(task_id) 实时监控（1s 间隔增量滚动输出）
          ├─ 任务完成 → 返回全部输出（截断20000字符）
          ├─ Ctrl+C → 只停监控返回（任务继续跑），AI 可再监控或 kill
          └─ 满 MAX_RUN_SECONDS=3600(1小时) → 自动 killpg 终止
kill_process(task_id) → killpg 手动终止（用户要求/AI判断失控）
process() 无参 → 列出所有后台任务
```

### 新建/修改文件

| 文件 | 说明 |
|------|------|
| `core/process_manager.py` | **新建**（115行）：BackgroundTask + ProcessManager 单例（register/get/list/remove/cleanup_finished） |
| `tools/process.py` | **新建**（226行）：ProcessTool，列表模式+实时监控模式 |
| `tools/kill_process.py` | **新建**（102行）：KillProcessTool，killpg+task.killed 标记 |
| `tools/terminal.py` | 超时分支：killpg → 注册后台任务返回提示；删 timed_out 死代码；description 更新 |
| `core/app.py` / `web/server.py` | 注册 ProcessTool + KillProcessTool |
| `commands/tools_cmd.py` | BUILTIN_TOOLS 14→16 个 + _write_tools_md 加后台任务管理段 |
| `cli.py` | 帮助 14→16 个 |
| `core/agent.py` | TOOLS_TEMPLATE 加"后台任务管理"段 |
| 13个Agent的 tools.md | 批量插入同段落（锚点：MCP 扩展工具名称格式行后） |
| `README.md` | 16大内置工具表 + 后台任务管理特性 |

### 关键设计点
- **输出共享**：terminal 的读线程在超时后继续 drain 到 out_chunks/err_chunks（daemon 线程不 join 放弃），ProcessManager 持有同一 list 引用，list.append GIL 原子安全
- **增量滚动显示**：每秒 `full_output()` 全量 decode，记录 shown_chars 切片增量 print（避免 chunk 边界切 UTF-8 字符的乱码问题）
- **Ctrl+C 语义**：process 监控中捕获 KeyboardInterrupt 返回"监控停止任务继续"（不 re-raise），与 terminal 执行中的 Ctrl+C（killpg+raise）不同——监控停≠任务停
- **tool_executor 显示**：process 列表用 display_output 简短摘要避免 print+executor 双重显示
- **1小时文案动态化**：`MAX_RUN_SECONDS // 3600` 格式化，防改常量忘改文案

### 测试结论
- sleep 4 timeout=2 → 3s 转后台返回 task_id ✅
- process 监控 → 实时滚动"进度_1/2/3"，完成返回全部输出 ✅
- Ctrl+C 停止监控任务继续 ✅ / kill_process 无残留 ✅
- 模拟 1 小时自动终止 ✅ / 正常命令+nohup 回归 0.0s ✅

## 七、process 监控实时状态行（补丁）

### 问题
监控头部"已运行 6s"只在进入时打印一次，固定不变。

### 修复
监控循环底部加**实时状态行**（每秒重绘）：
```
⏱ 已运行 Xs | Ctrl+C 停止监控 | kill_process(N) 终止
```
- 每秒 `\r\033[2K`（回车+擦除整行）清除旧状态行 → 增量输出 → 重绘新状态行（`end=''` 不换行）
- 新输出尾部无 `\n` 时先 `print()` 换行，保证状态行独占一行（否则清除时会误删输出尾部）
- 三个退出分支（任务完成/1小时自动kill/Ctrl+C）都先 `_clear_status()` 再打印结束信息
- 头部改为"（实时监控中）"不再含固定秒数

### 关键经验
- **底部状态行模式**：`print(status, end='')` + 下轮 `\r\033[2K` 清除重绘，与 wget/curl 进度条同理
- **独占一行原则**：状态行必须独占一行才能安全 `\033[2K` 清除；只有"本秒有新输出且尾部无换行"才需补换行（无新输出时清除状态行后光标本就在行首）
- 验证技巧：捕获监控输出，正则提取 `已运行 (\d+s)` 序列应有多个不同值；`out.count('\r\x1b[2K')` 等于重绘次数
