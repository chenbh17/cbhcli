## 一、更新概述

本次更新对 CLI 界面的聊天输入框进行了全面重构，解决以下历史问题：

| 问题 | 根因 |
|------|------|
| 终端窗口 resize 后显示重叠 | 旧实现使用固定宽度边框 `╭──╮`/`╰──╯`，窗口变化后边框宽度不匹配 |
| emoji / 中文退格错位 | 自定义 `bottom_toolbar` 补全菜单干扰 prompt_toolkit 光标追踪 |
| 输入框跳动 | 固定 10 行补全区域 + 手动行数计算清除输入框 |
| 按回车无法发送 | `multiline=True` 模式下 Enter 默认是换行，未显式绑定提交动作 |

## 七、踩坑记录

### 7.1 multiline=True 模式下 Enter 默认是换行

**现象**: 重构后按回车永远换行，无法发送消息和命令。

**根因**: prompt_toolkit 的 `multiline=True` 模式下，Enter 键默认绑定为换行（插入 `\n`），而非提交。旧代码有显式的 `enter` → `validate_and_handle()` 绑定，重构时漏掉了。

**修复**: 在 `_setup_keybindings()` 中添加:
```python
@self._bindings.add('enter')
def _submit(event):
    """Enter 提交（multiline 模式下需显式绑定）"""
    event.current_buffer.validate_and_handle()
```

**教训**: 使用 `multiline=True` 时，必须显式绑定 Enter 到提交动作。

### 7.2 旧实现的三个根本性问题

1. **固定宽度边框** — `╭──╮`/`╰──╯` 的宽度在初始化时计算，终端 resize 后不会重新计算，导致边框宽度与终端不匹配
2. **自定义补全渲染** — 在 `bottom_toolbar` 中手动渲染10行补全菜单，干扰了 prompt_toolkit 的光标位置追踪，导致 emoji/宽字符退格时光标位置计算错误
3. **手动行数清除** — `_print_user_input` 中手动计算输入占用的行数并用 ANSI 转义码清除，但 emoji/宽字符的显示宽度与字符数不一致，行数计算永远不准
