## 一、Web：聊天附件批量上传（一次请求多文件）

> 用户反馈：「文件上传按钮即便选择了多个文件，实际上传的只是第一个，只能一个个上传」

### 改动

- **后端** `web/server.py` `/api/chat/upload`：
  - `file: UploadFile` → `files: List[UploadFile] = File(..., alias="file")`
    （同一 FormData 里多个 `file` 字段一次收齐；单文件旧行为天然兼容）
  - 返回 `{"results": [...]}`：逐文件给出结果；**单个文件失败不影响其它文件**
    （失败项带 `error` 字段：超大/无文件名/写盘异常）
  - 每文件仍限 10MB；重名自动加 `_1/_2` 后缀逻辑不变
- **前端** `web/static/js/app.js`：
  - `api.chatUpload(files, a, m)`：把选中的**全部文件放进同一个请求**
  - `handleFiles`（按钮选择）与 `handlePaste`（粘贴多文件）统一走
    `uploadAttachments(list)` 批量入口；成功的进附件区、失败的逐条 toast
  - 多文件成功时提示「已添加 N 个附件」
- 缓存参数升至 `?v=5.4.2`，强制浏览器拉取新 JS（旧缓存也是"只传第一个"的可能诱因之一）

## 二、Web：文件管理器增强（更新时间 / 搜索 / 排序）

- **每行显示最后更新时间**（后端 `/api/files/list` 本就返回 `mtime`，前端补渲染）：
  - `n秒前` / `n分钟前` / `n小时前`；**超过 24 小时显示日期**（YYYY-MM-DD）
  - 悬停 title 显示完整时间（YYYY-MM-DD HH:MM:SS）
  - 悬停行时与文件大小一起隐藏、让位三点菜单（沿用既有交互）
- **文件名搜索**：面板上方新增搜索框，客户端即时过滤当前目录（不重复请求）；
  无匹配显示「（无匹配 "xx" 的文件）」
- **按更新时间排序**：搜索框旁排序按钮三态循环——
  `名称`（默认，文件夹在前+名称序）→ `🕒 新→旧` → `🕒 旧→新`；
  时间排序同样保持文件夹在前，组内按 mtime
- 目录数据缓存 `_fmLastData`：搜索/排序本地重渲染，零网络开销

## 三、Admin：审计日志三级分层（用户级 → 会话级 → 明细级）

> 用户反馈：「审计日志显示太细，没运行几天就上万条。改为分级显示，一层层查看后再显示最细那层」

### 层级设计

| 层级 | 数据来源 | 展示字段 | 交互 |
|------|----------|----------|------|
| **一级·用户级** | `GET /admin/api/events/summary_users`（events 按 user_id 聚合） | 用户、状态（运行中/在线/离线/已禁用徽标）、会话数、对话轮数、工具调用数、事件数、最后活动 | 点击行 → 钻取该用户会话级 |
| **二级·会话级** | `GET /admin/api/events/summary_sessions`（events 按 user+session 聚合，LEFT JOIN sessions 补元数据） | 会话标题（无标题回退截断 ID）、Agent、状态（运行中以内存注册表为准）、对话轮数、工具调用数、事件数、消息数、最后活动；分页（100/页） | 点击行 → 钻取该会话明细级 |
| **三级·明细级** | 原 `GET /admin/api/events` | 原事件表不变（时间/用户/类型/会话ID/摘要）+ 类型过滤 + CSV 导出 | — |

- **面包屑导航**：`👥 全部用户 › 👤 用户 › 💬 会话`，任意层级可点击回退
- **时间范围过滤（1h/24h/7d/全部）三级统一生效**；类型过滤与 CSV 导出仅明细级显示
- 用户级右上角保留「**查看全部明细 →**」直达按钮（跳过钻取，等价旧版平铺视图）
- **（无会话）事件组**（登录/管理操作等 session_id 为空的事件）在会话级单独成行，
  钻取时走新增的 `no_session=1` 过滤参数（`list_events`/`/events`/CSV 导出均支持）
- `__admin__` 伪用户在用户级显示为「🛡️ 管理员操作」
- store 层新增 `events_summary_by_user()` / `events_summary_by_session()`
  （GROUP BY 聚合 + COUNT/MIN/MAX + 条件 SUM 统计 tool_calls/rounds，走既有 recv_ts 索引）

### 四、Admin：会话查看 ANSI 乱码修复

> 用户反馈：「admin 页面查看用户会话有乱码：`[36m📤 输出:[0m`」

- **根因**：python 工具输出带终端颜色码（`\x1b[36m📤 输出:\x1b[0m`，python_tool.py），
  随快照/事件原样入库；管理页面直接以文本渲染 → ESC 不可见、`[36m` 裸露成乱码
- **修复（前端显示层清理，不动存储与 CLI 彩色显示）** `admin/static/js/app.js`：
  - 新增 `stripAnsi()`（与 Web 端同款正则，另加孤立 ESC 兜底）
  - `extractText()` 统一出口包裹 → 用户/AI/工具结果/系统四类消息渲染全覆盖
  - 实时画面 `liveAppendTool()`：工具参数与输出入库前先清理
  - `fmtPayloadValue()`：事件表与仪表盘活动流摘要同步清理
- **CSV 导出同步清理**（`admin_api._strip_ansi`，同时匹配原始 ESC 字节与
  json.dumps 转义后的 `u001b` 字面量形式）- 缓存参数 `__V__u6` → `__V__u7` 强制刷新管理页面静态资源
