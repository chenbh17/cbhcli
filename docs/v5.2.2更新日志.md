# v5.2.2 更新日志

## 跨进程配置同步（GlobalConfig / MCP / 链条 按 mtime 自动重载）

### 背景 / 根因
cbhcli 的 CLI、Web(18888)、Jupyter 插件是**三个独立进程**，各自启动时把配置加载进内存并缓存。任一进程改动配置（加模型 / 加 MCP / 建链条…）会写回磁盘，但**其他进程的内存副本不刷新**，导致在 CLI/Web 配好后，Jupyter 插件刷新页面也看不到新配置。

### 改动（核心：mtime 自动重载）
1. **`config/global_config.py`**：`GlobalConfig` 记录 `config.json` 的 mtime，新增 `reload_if_changed()`——mtime 变化时重新加载（仅当文件成功解析为 dict 才替换，避免读到半写状态）；`save()` 后刷新 mtime。
2. **`core/mcp_manager.py`**：`MCPManager` 记录 `mcp.json` mtime，新增 `reload_if_changed()`——重载服务器列表，断开并注销已删除服务器、连接新增服务器（尽力而为）；`_save_config()` 后刷新 mtime。
3. **`core/agent_chain.py`**：`ChainManager` 记录 `agent_chains.json` mtime，新增 `reload_if_changed()`——重载链条。
4. **`web/server.py`**：在 `get_config()` / `_get_mcp_manager()` / `_get_chain_manager()` 中调用对应 `reload_if_changed()`，使 Web 与 Jupyter 读取前自动感知其他进程的改动。

### 效果
任一进程改动配置后，其他进程**无需重启**即可在下次读取时看到最新配置（模型 / 备用模型 / MCP / 链条 / 设置等）。skills、知识库、历史本就是每次读盘，不受影响。

### 验证
直接改 `config.json` 加一个模型，Jupyter API 立即返回该模型（13→14），还原即恢复；直接改 `mcp.json` 加服务器，Jupyter MCP 列表立即显示。均无需重启。
