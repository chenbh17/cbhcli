# v5.1.7 更新日志

## 文本复读检测误报修复（TextLoopDetector）

### 问题现象
- 用户在 Web 端让 AI 设计 Trello 看板页面时，AI 的思考过程被提示"死循环"，思考被截断
- 排查确认：思考内容完全正常（逐步推进、有收敛），并非死循环

### 根因分析
`TextLoopDetector` 旧逻辑存在两个误报缺陷：

1. **单块 150 字符 + 全文计数**：取尾部单个 150 字符块，统计其在全文出现 ≥3 次即判复读。
   正常思考中"先设计后实现"的模式会**重复写出相同的模板/骨架片段**
   （如 HTML 头部 `<!DOCTYPE html> <html lang="zh-CN"> <head> <meta charset="UTF-8">...`），
   实测真实思考中该片段出现 ≥2 次（位置相隔 1.2 万字符），真实流中第 3 次出现时即误报。
2. **count 是子串计数，不区分上下文**：模板回述（设计草案 vs 正式实现）与真正的
   复读循环（连续输出相同内容、无进展）都被计为"重复"。

### 修复方案（改 `loop_detector.py` 1 个文件）
1. **双块判定**：取尾部 2×150=300 字符，要求双块**整体**在历史中重复出现。
   模板回述只有头部单块相同、后续内容不同（如两次 title 不同），双块不匹配 → 不误报。
   真正的复读循环连续输出相同内容，双块必然完全匹配 → 正常触发。
2. **近邻窗口**：只统计最近 `TEXT_LOOP_WINDOW=5000` 字符内的出现次数。
   思考中相隔上万字符的模板重复不算循环；连续复读在窗口内必然命中。
3. **触发阈值放宽至 15 次**（用户要求，极度保守）：`TEXT_LOOP_MAX_REPEAT=15`，
   即尾部双块在窗口内出现 **≥15 次**（含自身）才判定复读；窗口须 ≥ 双块×15
   （5000 ≥ 300×15），否则阈值不可达。
   行为：连续重复内容总长 < 4500 字符（15×300）时永不触发——正常思考中的
   偶发重复片段完全免疫；真正的死循环（模型持续输出垃圾重复）一旦超过 15 遍立即截断。
   调用方（CLI ai_handler.py / Web server.py）零改动，默认参数自动生效。

### 验证结果（max_repeat=15, window=5000）
| 场景 | 结果 |
|------|------|
| 真实思考文本（HTML 模板出现 2 次） | ✅ 不触发 |
| 思考中第 3 次写 HTML 模板（title 不同，正常推进） | ✅ 不触发 |
| 相同 HTML 模板连续 10 遍 | ✅ 不触发 |
| 相同重复单元 14 遍（差 1 次） | ✅ 不触发 |
| 相同重复单元 15 遍 | ✅ 触发（第 15 遍时） |
| 重复单元 30 遍 / 逐字重复 6000 字符 | ✅ 触发 |
| 短文本 <600 字符 | ✅ 不检测 |
| truncated_text 截断 | ✅ 有效 |

### 教训
- 死循环检测的本质是识别**"无进展的连续重复"**，而非"内容相似"。
  统计重复时必须考虑：重复的连续性（近邻）与重复的粒度（多块整体）。
- 长思考（reasoning 流几万字）天然高度自相似（反复推敲同一难题、
  先设计后实现），检测阈值必须对"模板回述"免疫。
