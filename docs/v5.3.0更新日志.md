## 1. 新建会话第一轮运行中，切走再点回报"会话不存在"

**复现**：新建会话 A 发第一条消息（第一轮运行中）→ 点"新建会话"创建
B → 点侧边栏会话 A → toast 报"会话不存在"（A 明明显示"● 运行中"）。
第一轮结束后再操作则完全正常。

### 根因

`chat_load` 内存会话复用分支的逻辑漏洞（`cbhcli_pkg/web/server.py`）：

```python
fname = _find_history_file_by_id(agent_name, session_id)   # 磁盘找历史文件
if fname and not _live_session_stale_vs_disk(live, fname):  # ← 漏洞
    ...复用内存会话...
```

复用条件**隐含要求磁盘上存在该 id 的历史文件**。而新建会话第一轮
运行中，每轮对话自动保存（autosave，v5.2.6）尚未执行（每轮结束才落盘）
→ 磁盘无文件 → `_find_history_file_by_id` 返回 None → 复用分支被
跳过 → `filename` 为空 → 按 id 的 glob 兜底也找不到文件 → 404。

第一轮结束后已落盘、fname 非空 → 复用正常——这正是"只有第一轮出
问题"的原因。侧边栏"● 运行中"徽标来自内存注册表（`_sessions_by_id`），
于是出现"显示运行中却说不存在"的自相矛盾。

### 修复

磁盘无文件（`fname is None`）时，内存副本是**唯一真相来源**（不存在
外部进程更新磁盘导致的过期问题），直接复用：

```python
if fname is None or not _live_session_stale_vs_disk(live, fname):
```

已落盘的会话仍走原有新鲜度校验（CLI 等外部进程更新磁盘时从磁盘重载）。

## 2. 连锁修复：运行中会话导出消息双份渲染

404 修复后暴露的次生问题：`_live_export_limit` 旧写法

```python
return getattr(cs, "run_start_msg_count", 0) or None   # ← 漏洞
```

在第一轮运行时（`run_start_msg_count=0`）把"截断到 0 条"错误变成
"不截断"——全量导出含本轮 user 消息，与 WebSocket 回放的 `run_start`
事件（`renderIncomingUserMessage`）双份渲染 user 气泡。

修复：0 也是有效截断（`max(0, int(...))`），会话运行中导出消息一律
截断到本次运行开始处，当前运行的内容由事件日志回放渲染（保证多浏览
器一致，v5.2.9 既有语义）。

> 通用教训：`x or None` 把合法值 0 吞成 None 是隐蔽的逻辑漏洞——
> "空/零值也有语义"的场景必须显式判空（`is None`），不能用 or 短路。

## 验证

- 独立单测 9 项全过：本 bug 场景 + 4 个回归场景（已落盘复用 / 内存
  过期磁盘重载 / 重启按 id 找回 / 真不存在仍 404）+ 导出截断语义
- 反向验证：临时还原修复前代码，测试精确复现 404（证明测试有效）
- 端到端（临时 agent + 纯 API 零 LLM）：新建会话 B → 新建 C →
  `load(session_id=B)` 返回 200 且正确复用（修复前 404）

## 3. 压缩上下文报错 NoneType has no attribute "strip"（qwen3 等思考模型）

**复现**：模型配置为 qwen3.8-27b（思考模式默认开启），上下文压缩时失败，
错误信息为 `'NoneType' object has no attribute 'strip'`。

### 根因

`LLMClient.chat()`（`cbhcli_pkg/core/model.py`）直接链式取值并 strip：

```python
return result["choices"][0]["message"]["content"].strip()
```

思考模型（qwen3 系列）在思考阶段耗尽 `max_tokens` 时，API 返回
`content=null`（内容全在 `reasoning_content`，`finish_reason=length`），
对 None 调 `.strip()` 即抛 `AttributeError`。异常被 `compress()` 捕获后
写入 `last_error` 展示，用户看到的就是这句 NoneType 报错——既崩溃又无
诊断价值。压缩摘要请求走 `skip_thinking=True`（不带 thinking 参数，
v5.2.4 对不支持 disabled 的 API 的兼容做法），qwen3 部署端默认思考开启，
该参数无法关闭它，思考 token 计入摘要预算 → 预算被烧光 → content=null。

### 修复（三层）

1. **安全提取**：`content`/`reasoning_content`/`finish_reason` 均安全
   取值（None→空串），不再链式崩；
2. **一次翻倍重试**：`content` 空 + `finish_reason=length` + 请求带
   `max_tokens` → 说明截断发生在思考阶段，`max_tokens` 翻倍（封顶
   `SUMMARY_MAX_TOKENS`=64k）重试一次——多数场景思考完成后能正常产出
   正文，压缩直接成功；
3. **诊断性异常**：仍为空则抛出可读错误（含 finish_reason、思考内容
   字符数、max_tokens 值、"建议调大 max_tokens 配置或关闭思考模式"），
   由 `compress()` 优雅捕获 → 会话保持原样不污染，`last_error` 可指导
   用户自行修复。

非流式 `chat()` 仅两处调用方：压缩摘要（compressor）、图片识别 fallback
（image 工具），均有异常捕获，行为兼容。

**验证**：mock 单测 9 项全过（正常返回 / 翻倍重试成功且预算正确 /
重试仍空抛诊断 / stop+空不重试 / 空串 / 封顶不重试 / compressor 端到端
失败优雅且 last_error 可读）。

> 教训：API 响应字段（content）**任何时刻都可能是 null**，链式取值后
> 直接调用字符串方法 = 崩溃；失败信息必须可诊断（为什么空 + 怎么办），
> 而不是裸异常文本。

# v5.3.0 QQ Bot 修复追加（2026-08-29，版本号不变）

## 1. QQ Bot 重连失败修复：网关鉴权头 Bearer → QQBot

**现象**：两个 QQ Bot 运行一段时间后疯狂重连失败，日志刷屏
`完整重连失败 (第N次)` + `获取网关地址失败`，QQ 消息收不到。

**根因**：QQ 官方 API 近期收紧鉴权头校验——`gateway.py` 的
`_get_gateway_url()` 用 `Authorization: Bearer {token}` 请求网关地址，
现在被拒绝（实测返回 `401 {"message":"请求头Authorization参数格式错误","code":11241}`）。
而 `api_client.py`（发消息用）一直是正确的 `QQBot {token}` 前缀，所以
"能收到消息时能回复、断线后连不上"。

**修复**（`cbhcli_pkg/qqbot/gateway.py`）：
- `Authorization: Bearer {access_token}` → `Authorization: QQBot {access_token}`；
- 补充 `X-Union-Appid` 头（与 api_client 对齐）；
- docstring 记录该坑防止回归。

**验证**：两个 Bot（qqbot/gyx-qqbot）实测 `_get_gateway_url()` 均成功返回
`wss://api.sgroup.qq.com/websocket`。

## 2. qqbot_send_message 工具支持主动发送（不需要用户先发消息）

**原限制**：工具只能"回复刚发过消息的用户"——openid 只存在内存
`message_handler._contexts`（按 Bot 实例），进程重启即丢、其他进程/Agent
拿不到；且没有 Bot 运行时 `restart_bot()` 会在多进程间引发网关连接竞争。

**修复方案**：

| 文件 | 变更 |
|------|------|
| `qqbot/qqbot_registry.py`（新增） | 用户注册表：所有与 Bot 交互过的 openid 持久化到 `~/.cbhcli/qqbot_registry.json`，跨进程共享；`record_user`（读-合并-写多进程安全） / `find_by_name` 昵称模糊查找 / `get_recent` 最近活跃 / `format_list` 列表 |
| `tools/qqbot_send.py`（重写） | ① `target_id` 直接指定 openid 主动发送 ② `find_user="昵称关键词"` 按昵称查 openid ③ `action="list"` 列出全部已知用户 ④ `bot_name` 指定用哪个 Bot ⑤ 发送走 REST API（纯 API 实例兜底），**不再 restart_bot**（消除多进程网关竞争）⑥ QQ 官方错误码翻译（主动消息频控/无好友关系等给出可操作建议） |
| `qqbot/message_handler.py` | `handle_event` 开头挂接 `registry.record_user`——每条收到的 c2c/群消息自动记录发送者 openid+昵称，尽力而为不阻塞主流程 |
| `core/agent_chain.py` | 链条下游 Agent 注册表也挂 `QQBotSendTool`（共享主 app 的 qqbot_service），链条场景可主动发 QQ 消息 |

**QQ 官方规则**（工具描述已告知 AI）：
- 主动消息：每用户每月仅 4 条，用户可在 Bot 资料卡关闭"主动消息"开关；
- 被动回复：收到消息 60 分钟内带 msg_id 回复不限次；
- 发送失败时错误信息携带官方 err_code 与处理建议。

**实测**：注册表预填后 `action=list`/`find_user` 正常；指定 openid 真实
发送成功（消息经 qqbot Bot 送达用户 QQ）。

## 3. qqbot_send_message 全 Agent 可用修复（Web 端补注册 + Agent 使用说明补全）

**问题现象**：除 qqbot 相关 Agent 外，其他 Agent（main/cbhcli/iptables 等）
不知道如何调用 `qqbot_send_message`，甚至调用时提示"注册表里没有相关工具"；
但 `/tools list` 和 Web 工具视图里又显示该工具存在，状态自相矛盾。

**根因**（两个独立问题叠加）：

1. **Web/Jupyter 端工具注册表缺失（核心 bug）**：CLI 与 Web 是两套独立的
   工具注册表构建代码——CLI 在 `app.py _init_tools()` 注册了
   `QQBotSendTool`，但 Web/Jupyter 端 `web/server.py _build_tool_registry()`
   完全没有注册。导致 Web 界面上任何 Agent 调用 qqbot_send_message 都会
   返回"工具名无法识别"。v5.3.0 改造时只补了 CLI（app.py）和链条
   （agent_chain.py），漏了 Web 端。
2. **"工具列表显示有"是假象**：`/tools list` 与 Web 工具视图显示的是
   `tools_cmd.py BUILTIN_TOOLS` **硬编码清单**（含 qqbot_send_message），
   与真实运行时注册表无关；同时 9 个现有 Agent 的 `tools.md`（注入系统
   提示的工具使用指南）只有 iptables 写了用法说明，其余 8 个 Agent 对
   该工具一无所知，自然不会调、也不会调对参数。

**修复方案**：

| 文件 | 变更 |
|------|------|
| `web/server.py` | ① 新增 `_get_qqbot_service()`：Web 进程级 QQBotService 单例（惰性创建，仅管理 REST API 发送，不连 WebSocket 网关，与 CLI 进程互不干扰）② `_build_tool_registry()` 补注册 `QQBotSendTool`（try/except 静默，QQ 模块异常时跳过不影响其他工具）——Web/Jupyter 端所有 Agent 立即可用 |
| `core/agent.py` | `TOOLS_TEMPLATE`（新 Agent 默认 tools.md 模板）新增 qqbot_send_message 使用说明章节 + 最佳实践指引行 |
| 9 个 Agent `tools.md` | 批量补全：iptables 旧简版章节替换为完整版（补 target_id/action=find_user/bot_name 参数与主动发送语义）；main/cbhcli/gyx-qqbot/nginx-helper/qqbot/repo/sml/test 共 8 个追加完整章节 |

**工具说明核心内容**（注入所有 Agent 系统提示）：
- `target_type`: "c2c"（私聊）或 "group"（群聊）
- `target_id`: 目标 openid（不是 QQ 号），留空自动用最近活跃用户
- `action='list'` 列出所有已知用户 openid；`find_user='昵称关键词'` 模糊查找
- `file_path`: 发送图片/文件的本地绝对路径
- `bot_name`: 指定用哪个 Bot（留空自动选择）

**生效方式**：
- Web 端：重启 Web 进程后立即生效（所有 Agent 重建工具注册表）
- CLI 端：本来就已注册，重启会话后 tools.md 新说明进入系统提示
- Agent 工作空间 tools.md 即时生效（会话内 Agent 文件更新事件会重建系统提示）
