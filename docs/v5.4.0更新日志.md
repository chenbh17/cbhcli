# v5.4.0 更新日志

> 发布日期: 2026-09-13
> 主题: **内网用户认证与审计系统**（含 cbhcli-admin 管理服务）——四端统一认证 + 全链路审计上报
> 对应需求文档: `cbhcli_用户认证系统_用户提示词.md`

## 背景

cbhcli 在内网多用户环境使用（CLI 终端 / Web 界面 / JupyterLab 插件 / exec 无头模式四端），
此前无用户认证：任何人安装后即可使用，且无从审计"谁在什么时候运行了什么会话"。

v5.4.0 引入完整认证与审计体系：
- **四端统一认证**：登录一次（设备级凭据）即四端通行；未登录时各端被拦截
- **管理服务 cbhcli-admin**（端口 28888）：管理员主密码门 + 用户管理（创建/禁用/删除/
  重置密钥/续期）+ 会话浏览 + 实时监控 + 权限查看 + 审计日志
- **三段式审计上报**：会话状态流（心跳）/ 事件流（工具调用/权限拦截/模式切换等）/
  会话快照（完整对话，本地删除后管理端仍保留）

## 四、协议要点

- **凭据**：`~/.cbhcli/auth.json`（0600）只存 token（不存原始密钥）；`expires_at=null` 表示永久
- **密钥**：`cbhk_` + 32 字节随机；服务端存 `sha256(salt+key)`；仅创建/重置时一次性显示
- **Token**：`cbht_` + 32 字节随机；服务端存 sha256；有效期按用户策略（7/30/90/365 天/自定义/**永久**）；
  支持滚动续期（剩余<2 天）+ 管理页面一键续期（已过期用户无感恢复）；重置密钥（key_version+1）全员踢下线
- **三段式上报**：状态流（心跳 60s）/事件流（批量 2s）/快照（每轮去重）——任何一段失败不影响其他段与对话
- **断网策略**：软在线（默认，服务故障不阻塞已登录用户，恢复后补传）；strict_online 开关备用

## 九、发布后修复

### 修复 1：CLI 未登录提示框右侧竖线不对齐（用户反馈）

**现象**：`🔐 未登录 — 无法发起对话` 提示框右侧 `│` 参差不齐（不是一条竖线）。

**根因**：方框用**手工空格**对齐（`guide.login_hint_text` 中按视觉估算空格的字符串常量），
中英文/emoji 混排时必然错位（手工估算的列宽 ≠ 实际显示宽度）。

**修复**：`auth/guide.py` 新增 `_boxed(lines)` —— 用项目既有的字素簇宽度工具
（`core/text_width.display_width`，emoji/VS16/ZWJ 感知）动态计算最宽行并逐行补齐，
右侧竖线严格对齐；宽度模型与用户终端（xterm.js：emoji=2、Ambiguous=1）一致。

**验证**：逐行 `display_width` 全部相等（60 列，含 emoji 行）；已安装版本实测输出对齐。

**教训**：**CLI 任何"右侧对齐"的方框/表格禁止手工空格**——必须走 `text_width` 动态补齐
（与 `_show_welcome` 面板同一套做法）；emoji 与 Ambiguous 字符（—、·）的列宽以
`wcwidth` 模型为准（xterm.js/VTE 默认一致）。

### 修复 2：含 emoji 行仍偏 1 格（方框内禁用 emoji，用户二次反馈）

**现象**：动态对齐后，**含 🔐 的行**右侧边框仍偏左 1 格（提示框第二行、欢迎面板倒数第二行）。

**根因**：**用户终端（Jupyter 终端 = xterm.js）把 emoji（🔐）渲染为 1 列**，而 `wcwidth`
模型算 2 列 → 该行实际显示比模型窄 1 → 补齐后右侧边框偏左 1 格。
（实测确认：`—` 等 Ambiguous 字符不偏、仅 emoji 行偏 1，即 emoji 宽度是唯一差异源。）

**修复**：**所有"右侧闭合对齐"的框内禁用 emoji**，统一改用宽度恒定的 `●`（U+25CF，宽度 1）：
- `auth/guide.py`：`🔐 未登录` → `● 未登录`
- `core/app.py` `_show_welcome` info4：`🔐/👤` → `●`
- `admin/server.py` 启动 banner：改为 `_double_box()` 动态宽度（并去除框内 emoji）

**验证**：直接调用输出函数捕获 stdout（不经 pty——pty 抓取受 prompt_toolkit 重绘影响
会把 `─` 换成光标移动序列导致误判），欢迎面板 13 行 + 提示框 10 行 + admin banner
逐行 `display_width` **全部相等**且无 emoji。

**结论（通用规则）**：终端的 emoji 宽度不可信（同机不同终端都可能不同），
凡需要"右侧闭合对齐"的框（`╭╮`/`╔╗`/`┌┐`）内部一律只用 ASCII + CJK + `●○◆▸`（U+25xx）。

### 修复 3：内置默认口令 hash 化（分发安全，2026-09-14）

**背景**：分发 whl 给他人部署时，`unzip` 可直接看到 `DEFAULT_MASTER_KEY = "chenbh17"` 明文 →
拿到包的人可用默认密码进入**自己部署的**管理后台（"改自己服务器密码"管不到别人部署的机器）。

**方案 2 落地（随机强口令 + 仅存 hash）**：
- `admin/master.py`：内置默认改为 `DEFAULT_MASTER_KEY_HASH` + `DEFAULT_MASTER_KEY_SALT`
  （`sha256(salt+口令)`，源码/whl **不含明文**）；口令为随机强口令（14 位、字母数字混合，
  非弱口令——离线穷举不可行）；口令由发行方掌握，实际部署建议用 env / `--set-password` 设置自己的
- `admin/server.py`：移除 `DEFAULT_MASTER_KEY` 导入
- 文档与长期记忆：去除明文说明
- 本机实机同步：crontab `CBHCLI_ADMIN_MASTER_KEY` + `admin.json` hash 均更新为新口令
  （旧密码 `chenbh17` 立即失效）

**验证**：
- whl 内 `cbhcli_pkg/admin/` 全文件无 "chenbh17" ✓（剩余出现在 cbhpacks 的 SSH 用户名/路径默认值，非密码）
- 模拟"别人新部署"（干净环境+空数据目录）：输入 `chenbh17` → "❌ 主密码错误"；输入随机口令 → 启动通过 ✓
- 实机：新口令登录 HTTP 200 / 旧密码 HTTP 401 ✓

**注意**：修改主密码时 **env（crontab）与 admin.json 必须同步**——env 优先级最高，
只改一边会出现"实际仍接受旧密码"的假象。

### 2. 会话管理

**② 运行中会话实时画面（WebSocket）**
- 管理服务端新增 `/admin/ws`（query token 认证；每连接独立出站队列 + 单 sender 串行发送；
  积压丢最旧、不允许拖垮上报链路）
- `/api/report/batch` 收到事件后实时广播（**仅广播实际入库事件**——`insert_events(accepted_out=...)`
  收集，eid 幂等去重后的事件不重复推送）
- 客户端流式内容上报（CLI/Web/Jupyter/exec 四端统一）：
  - `reporter.report_stream_text(session_id, kind, text)` **聚合器**：≥400 字符或 0.8s 一批；

- WS 断线指数退避重连（1s→30s）+ 25s 应用层 ping/pong 保活

### 3. 实时监控

**① 运行中会话"闪烁/消失"根因修复（多进程心跳互相覆盖）**
- 根因：`live.update_running(replace=True)` 按**用户**整体替换运行集合——Web 服务 / Jupyter
  等常驻进程每 60s 上报的空 `running_sessions` 会把 CLI 正在运行的会话从注册表删除
  （60s 后 CLI 心跳又加回）→ 看板约一半时间不可见
- 修复：客户端新增**进程实例标识** `instance_id`（reporter 生成 `i_<uuid12>`；心跳与
  `session_status` 事件携带）；服务端 `live.update_running` 按实例隔离——全量替换只清理
  **本实例拥有**的条目；旧客户端（无 instance_id）归入 `legacy` 槽位
- 运行中判定 TTL 180s → **240s**（4 个心跳周期缓冲）
- 验证：真实多进程并存（web + jupyter + CLI 三进程心跳）下 135s 长任务全程可见 12/12 次

**② 点击看板 → 实时交互画面**：监控卡片可点击（cursor pointer）→ 打开会话详情抽屉

## 补充迭代 2：交互细节打磨与加载提速（2026-09-15 第二批，同版本 v5.4.0）

> 主题：用户实测反馈四项——**密钥眼睛两态/完整显示**、**会话列表实时化**、
> **实时画面流式流畅度**、**Web 切换 agent 列表加载提速**；顺带修复"会话标题被空值覆盖"bug。

### 1. 用户管理（密钥眼睛）

- **眼睛两态**：默认浅色（`opacity: 0.38`），点击后深色（`opacity: 1`）——统一使用 👁 图标
  （不再在点击后切换为 🙈 猴子捂眼）
- **点击后完整显示密钥**：新增 `.key-cell.revealed` 状态（`white-space: normal; word-break: break-all`），
  此前受掩码态 `ellipsis` 影响 48 字符密钥被截断为 `cbhk_xxx...`

### 2. 会话管理（列表实时化）

- 新增 `autoRefreshSessions()`：**WS 事件触发**（700ms 节流）+ **5s 轮询兜底**——新会话/运行中状态
  实时上屏，不再需要手动点「刷新」
- 列表数据签名对比（session_id/status/message_count/last_heartbeat），无变化不重绘（避免闪烁）

### 2.1 权限快照（滚动条优化，用户反馈）

- 现象：Agents 区每个 agent 行**各自带一个横向滚动条**，视觉杂乱
- 修复：改为**整个列表共享一个横向滚动条**（`.list.li-single-scroll` 统一滚动容器；
  行宽随内容撑开 `width: max-content; min-width: 100%`）——滚动时所有行联动，
  内容全量可见（实测容器 scrollWidth 2057px / 可视 638px，弹窗内滚动容器仅 1 个）
- 滚动条配色：移除标准属性 `scrollbar-width`（Chromium 下它会**禁用**
  `::-webkit-scrollbar` 自定义样式、滚动条退回系统浅色主题）——现为深色（实测像素 #1e2229，
  与深色主题融合）

### 3. 实时画面（流式流畅度）

- 客户端聚合阈值：0.8s/400 字符 → **0.18s/120 字符**（静置兜底 1.5s→0.8s）——更接近连续流式
- 前端实时区渲染改为**增量追加**：每个 chunk 只向对应块 `append` 文本节点，
  **不重建 DOM**（此前每 0.8s 全量重建导致"一顿一顿"；快照刷新后仍走一次性重建）
- 实测（真实 exec 输出 546 字符）：26 批 stream_chunk，**到达间隔中位数 218ms**
  （P90 390ms；此前 ~800ms 一批）

### 4. Web 界面切换 agent 加载提速

- `onAgentChange`：侧边栏列表刷新**提前并行执行**（此前排在 `restoreMessages` 之后——
  大会话恢复时列表要等数秒才更新；实测优化后列表 **185ms** 内更新）
- `restoreMessages` 自动恢复会话：先用 `workspace/info`（毫秒级、已按作用域过滤、含最后对话时间）
  挑候选，最多尝试 5 个；替代原先盲目尝试最多 10 个（每个被拒会话都要完整解析文件后才 403）
- 服务端 `_load_session_core`：作用域预检提前——用文件头 8KB 元数据
  （新增 `SessionHistoryManager.get_meta()`，带缓存）先判 403，被拒会话省 10~30ms/个

### 5. 修复：会话标题被空值覆盖

- **现象**：CLI 会话轮结束后，管理页面会话列表中该会话**标题变空**
- **根因**：CLI 轮结束的 `idle` 状态事件不带 `title`/`workspace`；服务端 `_apply_status_event`
  用空值 `upsert_session` 覆盖了已有标题
- **修复**（三层）：
  ① 客户端 `report_status(idle)` 从运行条目兜底 title/workspace/agent/surface；
  ② 服务端 `_apply_status_event` 只收非空字段（空值不覆盖）；
  ③ `live.set_session_status` 改**合并语义**（保留既有字段，避免信息更少的后续更新覆盖）

### 6. 其他

- 管理页面静态资源缓存参数 `__V__u2`→`__V__u3`→（滚动条修正）`__V__u4`→`__V__u5`；
  Web 界面 `?v=5.4.0.1`→`?v=5.4.0.2`
