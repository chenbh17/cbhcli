## 问题1+5 详解：字素簇宽度补丁

### 根因

prompt_toolkit 的 `get_cwidth()` 对多字符字符串**逐字符求和 wcwidth**，对复杂 emoji 字素簇计算错误：

| 字符 | prompt_toolkit 计算 | 终端实际渲染 | 偏差 |
|------|--------------------|--------------|------|
| ❤️ (U+2764 U+FE0F) | 1 | 2 | 退格错位1列 |
| 👨‍💻 (ZWJ序列) | 4 | 2 | 错位2列 |
| 🇨🇳 (旗帜) | 4 | 2 | 错位2列 |
| 👍🏻 (肤色修饰) | 4 | 2 | 错位2列 |

光标定位错误 → 退格重叠/错位；且屏幕模型被污染后，整个会话后续渲染持续错位
（包括 resize 时的多行重叠、补全菜单显示异常）。

### 修复

`text_width.py` 实现字素簇切分（ZWJ/VS16/肤色/组合符/旗帜对）与宽度计算，
`install_prompt_toolkit_patch()` 替换 prompt_toolkit 模块级全局 `_CHAR_SIZES_CACHE`
（`get_cwidth()` 内部查询该缓存），一次替换全局生效，无需修改 prompt_toolkit 本身。

主流参考：现代终端（GNOME Terminal/Windows Terminal/iTerm2）与 Claude Code 等
均按字素簇渲染 emoji，宽度模型与终端一致是正确光标定位的前提。

## 问题3 详解：edit 预览动态布局

### 旧实现问题
- 固定左右并排（每列75字符，共153列），终端宽度不足时左右内容交叉重叠
- 分隔线 151 列 vs 数据行 155 列，表格不对齐
- 逐字符 east_asian_width 计算，emoji 内容对不齐

### 新实现
- `shutil.get_terminal_size()` 获取终端宽度
- **宽屏（≥115列）**：左右并排，pane 宽度 = (终端宽-5)/2 动态计算
- **窄屏（<115列）**：上下堆叠（原内容块 → 分隔线 → 新内容块），内容全宽
- 所有行严格等宽（含标题条/分隔线/数据行），字素簇宽度精确对齐
- write/python 预览截断宽度同步自适应终端

## 问题4 详解：并行子Agent

### 设计（参考 Claude Code Task 工具）
- 新工具 `delegate_tasks`：接受 2~6 个**相互独立**的子任务
- AI 根据任务复杂度智能决定拆分数量（工具描述引导：简单不拆，复杂拆2~4个）
- `ThreadPoolExecutor` 最多 4 并发，超出按波次执行
- **全部子Agent完成后**，汇总结果作为单个 ToolResult 返回，主Agent继续

### 关键技术
- `_ThreadStdoutProxy`：按线程分发 stdout，工作线程输出进各自 StringIO
  缓冲区互不混杂，主线程直通真实 stdout 打印进度
- 并行期间 `tool_executor.no_more_confirmations=True`（多线程无法安全交互确认）
- 并行子Agent禁用 rich.Live 思考显示（ThinkingDisplay.enabled=False）
- 并行子Agent系统提示追加"禁止使用 ask_user"
- CLI 端：每完成一个子Agent即打印进度并回显其完整执行过程
- Web 端：转录文本去 ANSI 后随结果返回前端
- 只有1个子任务时自动退化为串行 delegate_task
