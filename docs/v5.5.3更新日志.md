## 一、功能说明

| 按键 | 功能 |
|------|------|
| `Ctrl+Z` | 撤销聊天输入框的上一次文本变更（文本 + 光标位置一起恢复） |
| `Ctrl+Y` | 重做被撤销的文本变更 |

行为细节：

- **粒度 = 一次文本变更**：逐键入每个字符一步；整段粘贴一步；`Ctrl+U`/`Ctrl+K`/
  `Ctrl+W` 等剪切操作一步（剪切内容可用 Ctrl+Z 恢复）。
- **连续撤销/重做**：可多步撤销到空输入，再逐步重做恢复；光标位置随快照恢复。
- **新输入清空重做栈**：撤销后键入新字符，重做历史即失效（标准编辑器语义）。
- **提交后重置**：Enter 发送后 Buffer reset，撤销/重做栈清空，下一条消息从零开始。
- **请求运行中可用**：AI 回答期间输入框本就可编辑（草稿保留），撤销/重做同样生效。
- **作用范围 = 聊天输入框**：应用内模态（/login、/model add 等向导输入）不受影响，
  保持原有行为。
- `Ctrl+Y` 原为 prompt_toolkit 默认 emacs 的 yank（kill-ring 粘贴），按用户要求改为重做；
  `Ctrl+Z` 原默认行为是**插入字面控制字符 0x1A**（不可见脏字符），现改为撤销。

## 二、实现方式（零自造栈，复用 prompt_toolkit 内置机制）

prompt_toolkit（3.0.43 / 3.0.52 均具备）的 `Buffer` 内置
`_undo_stack` / `_redo_stack`（`(text, cursor_position)` 快照栈）与
`save_to_undo_stack()` / `undo()` / `redo()` 方法；`KeyProcessor._call_handler`
在**每个键位 handler 执行前**自动 `save_to_undo_stack()`（`handler.save_before`
默认 True）——即撤销栈随日常输入自动填充，无需自行埋点。

本次只在两个输入宿主各加两条键位绑定：

- `core/ui/shell.py`（全屏 TUI，`_setup_bindings`）：
  `c-z` / `c-y` → `event.current_buffer.undo()/redo()`，
  filter `has_focus(buf)`（仅聊天输入框聚焦时生效，模态期间不拦截）。
- `core/input_box.py`（legacy 内联，`_setup_keybindings`）：
  `c-z` / `c-y` → 同上（PromptSession 自定义键位优先于默认 emacs 键位）。

### ⚠️ 关键细节：`save_before=lambda e: False` 必不可少

`KeyBindings.add` 的 `save_before` 默认 True → 键位处理器在 handler 执行前会先
`save_to_undo_stack(clear_redo_stack=True)`：

1. 对 **redo**：执行前先把 redo 栈清空 → `redo()` 永远无栈可弹，**Ctrl+Y 彻底失效**；
2. 对 **undo**：连续第二次撤销时，预保存会清掉第一次撤销刚压入的 redo 快照 →
   多步撤销后重做丢失中间状态。

因此两条绑定都必须 `save_before=False`（prompt_toolkit 默认 emacs 的
`c-_`/`c-x c-u` undo 绑定同样如此处理）。`redo()` 内部自带
`save_to_undo_stack(clear_redo_stack=False)`，无需外部补快照。

## 三、测试

新增门禁 `tests/ui/check_undo_redo.py`（全屏 + legacy 双模式，pty 驱动真实按键）：

- A 基础撤销：`abcd` + Ctrl+Z → 提交 `abc`；
- B 撤销×2 + 重做×2：`abc → ab → a → ab → abc`（专杀 save_before 缺省 bug）；
- C `Ctrl+U` 整行剪切后 Ctrl+Z 恢复 `hello`；
- D 撤销后输入新字符 → redo 栈清空（Ctrl+Y 无效果）→ 提交 `ac`；
- E 空缓冲上 Ctrl+Z/Ctrl+Y 安全无副作用；
- 断言**提交序列完全一致** + Ctrl+D 正常退出 + 无 Traceback。

⚠️ 测试手法沿用 v5.5.0 教训：全屏是单元格级差分重绘，**不能在原始字节里找整行
文本**（SGR 复位码会插在文本与换行之间）——提交文本改由子进程写 `SUBMIT_LOG`
文件做精确断言，渲染层只作旁证。

回归：`tests/ui/` 全部 **30 套件通过**（29 旧 + 1 新；`/usr/bin/python3`，
prompt_toolkit 3.0.52）。
