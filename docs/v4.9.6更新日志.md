# CBHCLI v4.9.6 更新日志 — 模型切换体验优化

> 本次更新修复两个模型切换相关问题：`/model use` 切换模型不再丢失会话；视觉主模型 fallback 到非视觉模型不再报错。

---

## 一、`/model use` 切换模型保留会话内容

### 问题
CLI 下 `/model use` 切换模型后，调用链为 `_use_model()` → `app._load_agent()` → `_reset_session()`，**整个会话被重建**，当前对话上下文全部丢失。

### 修复
新增 `CBHCLIApp.switch_model(model_config)` 原地切换方法，`_use_model()` 改为调用它：

```python
def switch_model(self, model_config: dict):
    self.llm_client = LLMClient(model_config)           # 替换 LLM 客户端
    self.token_counter = get_token_counter(...)         # 同步 token 计数器
    self.context_compressor = ContextCompressor(...)    # 同步压缩器
    if self.context_window:                              # 更新上下文窗口限制
        self.context_window.model_limit = self.llm_client.context_limit
    self._update_system_prompt()                        # 原地更新系统提示
```

- **会话消息全部保留**（不再经过 `_reset_session`）
- 系统提示原地更新（复用既有 `_update_system_prompt()`，模型名/视觉能力描述随新模型刷新）
- 切换成功提示增加"当前会话内容已保留"

### 影响文件
- `cbhcli_pkg/core/app.py`：新增 `switch_model()`（+23 行）
- `cbhcli_pkg/commands/model_cmd.py`：`_use_model()` 改用 `switch_model()` 替代 `_load_agent()`

## 二、视觉主模型 fallback 到非视觉模型报错

### 问题
主模型为视觉模型时，会话中可能含带图多模态消息（image 工具直发 / Web 上传）。主模型异常 fallback 到非视觉备用模型后，多模态消息原样发送被 API 拒绝，报"xxx 模型不是视觉模型"错误，导致 fallback 失效。

### 修复
在 `LLMClient._clean_messages()`（`chat()`/`chat_stream()` 发送前的唯一收口，含重试路径共 4 处调用点）增加降级逻辑：

- **非视觉模型**（`supports_vision=False`）：发送前将多模态消息（content 为 list）降级为纯文本——保留全部 text 部分，image_url 部分替换为占位说明 `[已省略 N 张图片：当前模型不支持视觉]`
- **视觉模型**：行为不变，多模态消息原样发送

```python
# model.py _clean_messages 开头
if not self.supports_vision:
    messages = [self._strip_images(msg) for msg in messages]
```

这样非视觉 fallback 模型能接续对话（知晓曾有图片但不可见），不再报错中断。字符串 content 消息不受影响；该修复同时覆盖 CLI 与 Web 的 fallback 路径（均经 LLMClient 发送）。

### 影响文件
- `cbhcli_pkg/core/model.py`：`_clean_messages()` 增加图片降级，新增 `_strip_images()` 静态方法（+30 行）

## 三、验证

- 语法编译全部通过
- 降级逻辑：非视觉模型输出全为纯文本、文本保留、占位说明正确；视觉模型多模态原样保留；纯文本消息不受影响
- switch_model：客户端/计数器/压缩器/窗口限制全部同步替换，会话消息 3 条完整保留，系统提示原地更新
