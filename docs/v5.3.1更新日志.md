## 一、cbhpacks 领域 Harness（确定性建模护栏）

Harness Engineering 理念落地到数据科学建模领域：**建模错误由规则代码确定性检查，不依赖 LLM 自觉**。
检查项分级：🟡 WARN（高风险+修复建议）/ 🔵 INFO（提示）；检查绝不抛异常、绝不修改数据。

### 1. 共享检查模块 `cbhpacks_guard.py`（新增）
纯函数式检查库（Finding/HarnessReport 数据结构），共 11 项检查：

| 组 | 检查项 | 说明 |
|----|--------|------|
| A 缺失填充 | A1 填充值≥非缺失最小值 | 填充值混入正常值区间污染分箱（仅对有缺失的列检查）|
| | A2 填充值与已有值冲突 | 分箱无法区分缺失与真实值 |
| | A3 缺失率>50% | 建议单独分箱/删除 |
| B 分箱质量 | B1 单好/单坏箱 | WOE 数学上必为 ±inf，列出问题变量（不再静默置0掩盖）|
| | B2 单箱占比>50% | 粒度太粗区分度不足 |
| | B3 小样本箱 | 箱样本 < max(30, N×0.5%)，噪音大 |
| | B4 WOE 非单调 | 提示关系复杂 |
| C 数据穿越 | C1 训练/测试时间重叠 | **场景化警告**：评分卡/OOT 必须按时间切；无时间语义横截面分析可忽略 |
| | C5 目标泄漏 | 单变量 IV>0.5 疑似 target 衍生变量 |
| D 过拟合 | D1 train/test 指标差 | AUC 差>0.05 / KS 差>0.1 |
| | D2 特征-样本比 | LR 特征数 > 正样本数/10 |
| | D3 CV 折数 | cv<5 提示不可靠 |
| | D4 test>AUC | 切分异常/泄漏信号 |
| E 稳定性 | E1 PSI 分级 | 0.1~0.25 漂移 / >0.25 严重漂移自动解读 |

**设计要点**：分箱粒度判断基于**分箱结果**（total_cnt 实际分布）而非 group 参数——千万级数据 15 箱完全合理；
C1 不做硬拦截（横截面分析随机打乱是正确操作），由场景决策。

### 2. 工具内置检查（cbhpacks_bins / cbhpacks_training）
- `comp_woe_iv` / `bins_rpt` 执行后自动做 B 组检查 + A 组填充检查，WARN 追加到输出
- `*_fit` 执行后自动做 D2（LR 特征样本比）
- `para_adj_gs/bs` 执行后自动做 D3（CV 折数提示）
- `report` 执行后自动做 D1/D4 过拟合对比 + C1 时间切分检查（report 已产出 train/test AUC/KS，直接比对）
- **IV inf 不再静默掩盖**：置 0 前先提取警告清单（B1）

### 3. 新工具 `cbhpacks_harness`（显式校验入口）
- method: `check_data`（A组）/ `check_bins`（B组）/ `check_leakage`（C1+C5）/ `check_overfit`（D1/D4）/ `check_stability`（E1）/ `check_all`
- AI 在建模关键节点主动调用：分箱后 → check_bins；切分后 → check_leakage；评估后 → check_overfit
- 结果注入 python 会话：`harness_report` / `harness_findings`
- 每次检查写入审计日志（tracer 新增 `harness_check` 事件，tool_executor 执行前自动注入 tracer）

### 4. 结构修复：data_to_woe 分箱参数自动继承
- 根因：工具层会话缓存 key 含 group 参数，comp_woe_iv 与 data_to_woe 两次调用参数不一致 → cache miss 新建实例 → 默认参数重新分箱（分箱/转换错位）
- 修复：① cache key 纳入完整分箱参数（group/adj_bin/min_group/cat_cols）；② data_to_woe 未显式传分箱参数时自动继承同数据集最近一次 comp_woe_iv 的参数

## 四、发布后实测修复（用户测试报告驱动，2026-08-25）

用户对 cbhpacks 全流程实测发现 2 个问题，已修复并同步部署到两套环境（~/.local + anaconda）：

### 1. get_psi 缺失处理 bug（问题A）
- **症状**：两月缺失率相近（19.6% vs 17.8%）但 PSI 报 2.0（虚假漂移），真实 PSI 仅 0.019
- **根因**：`bins_model.get_psi` 中 cmp 月数据 `pd.cut(...)` 前未 fillna（base 月走 get_bins 内部分箱已填充缺失、单独成箱），NaN 被 value_counts(dropna=True) 丢弃 → 分布失算
- **修复**：cmp 侧 `pd.cut(cmp_mth_data[i].fillna(self.nan), base_bin_edge)` + `reindex(base_grp_cnt.index).fillna(0)` 箱序对齐（防对齐 NaN 污染求和）
- **验证**：缺失率相同（20% vs 20%）的两月数据修复后 PSI=0.0026/0.0066（修复前量级为 2.0）

### 2. data_to_woe 跨数据集泄漏（问题B）+ C2 防护落地
- **症状**：对 test 集调 data_to_woe 时库内部自动重新分箱，WOE 基于测试集自身 bad_rate（违反"WOE 只在训练集计算"铁律）
- **库修复**：`bins_model` 新增 `apply_woe(new_df, woe_mapping=None)` 方法——用训练集映射对任意新数据转换、不重新分箱
- **工具层修复**：`cbhpacks_bins_model.data_to_woe` 新增 `woe_mapping_pkl` 参数（传训练集产出的 woe_mapping_*.pkl 即走 apply_woe 路径）；对无既有分箱记录的数据集自动触发 **C2 WARN**（数据穿越警告+正确做法指引）
- **踩坑**：C2 判断不能用"事后查缓存"（新建实例已入缓存会误判），必须 `not new_instance or 存在同数据集其他实例`
- **验证**：4 场景全过——同数据集无误报 / 跨数据集无映射触发 C2 / 带映射正确转换 / 重复转换无 C2

### 经验沉淀
- **"没找到问题"与"没提供数据"必须区分**——护栏类工具把空结果当输入错误返回，用户会误以为参数给错而放弃检查（反向也是假成功）
- **检查静默跳过 = 假成功**（Bug 2/4）：任何"无法执行"的检查必须显式告知"未执行+为什么+怎么办"，绝不能落入"✅ 全部通过"分支
- **验证特征字符串应选代码语句而非输出文案**：guard 修复后 f-string 里"无坏样本/好样本的箱"由 `{'/'.join(zero_parts)}` 拼接，grep 输出文案必然扑空
- **测试场景构造要先想清楚数据生成机制**：PSI 漂移测试用 `np.random.choice` 混合月份导致漂移不存在（PSI=0.0048 正确无警告），一度误判修复失败；改为月份关联漂移后验证通过
- **cbhpacks 库 bins_rpt 对单好/坏箱的 WOE/IV 直接置 0**（非 inf 直传）→ IV=0 与"真无区分度"不可区分，工具层必须补偿说明（Bug 14 实测发现）

### 经验沉淀
- **流式事件日志必须按块聚合**：按 delta 存储 + 上限裁剪 = 迟到回放必然丢失（长响应场景），聚合后日志规模从"字符块数"降为"内容块数"
- **进程退出路径上的通知必须同步发送**：守护线程在进程退出时被直接杀死，"结束通知"这类临终消息用异步 = 大概率丢失（CLI idle 徽标卡死实测）
- **跨进程"会话不存在"不等于异常**：CLI 会话不在 Web 内存注册表，`refreshStatus` 的"服务器重启找回"逻辑会误伤跟随视图——跨进程共享会话的场景，内存缺失是常态不是故障
- **回放已应答的确认卡会误导迟到观看者**：应答状态要写回事件日志（answered 标记），回放时直接渲染终态
- **同一交互会话有多个"所有权方"时（CLI/Web）**：只读跟随 + 结束后单方接管，避免两端同时写同一历史文件

## 第五轮：作用域基准修正 + /resume 目录层级（用户反馈驱动，2026-09-03 第二批）

### 问题1（修订）：作用域基准改为服务启动目录
- **背景**：第四轮把侧边栏作用域绑定到"当前工作空间"，导致选择某个子文件夹后主文件夹和兄弟文件夹的会话从侧边栏消失（用户要求全部显示）
- **修复**：`_ws_in_scope`/`_check_session_scope` 基准从 `_current_workspace` 改为 **`_SERVER_ROOT`（服务启动目录）**——侧边栏始终显示启动目录下全部子目录的会话分组，选择子文件夹只切换工作目录不缩窄视图；服务器根之外的会话仍被 403 拦截

### 经验沉淀
- **"作用域"的基准要钉死在服务启动目录而非当前工作空间**：工作空间是易变状态（选个子文件夹就变了），把它当过滤基准会"切换即缩窄"；服务启动目录才是用户心智中的"本服务管哪棵目录树"

- **CLI 参数解析先行排除 D 编号形式**：`d1` 会被关键词搜索分支误吞（load_session("d1") 必然 None），新增参数形式要在搜索分支前显式排除
